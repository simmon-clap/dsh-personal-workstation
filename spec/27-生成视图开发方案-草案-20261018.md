## 1 · 目标与完成判据

**目标（三句话）**：项目详情能生成"风险与证据"；知识能生成"多份材料对比"；任务能生成"卡在哪、等谁、下一步"。全部带出处、可保存、可复现、可回应。

**算完成**：真实实例 + 真实数据 + 桌面 1440 / 手机 390 + 截图；语义门禁 8 条全绿；`live-acceptance` 通过；账本写清做了什么 / 没做什么 / 证据 / 回滚。
**不算完成**：只有模板渲染没有真实数据；只有截图没有门禁；生成内容不带出处；视图打开一次就消失。

## 2 · 五个决策门（先拍板，后动工）

> 你 2026-10-18 拍板："最开始就按这 5 个决策门来做；先不开发，先把规范与规划准备好。"
> **D6–D10 原定五项；D11 是今天新增的架构归属问题（OpenUI 插件思路）。**

### D6 · 范围：先做一处还是三处

| 选项 | 影响 | 建议 |
| --- | --- | --- |
| A. 先项目详情一处 | 1 个模板 + 1 个入口，最快验证底座 | ✅ 推荐 |
| B. 项目 + 知识 + 任务一起 | 3 处同时改，门禁与验收翻倍；任一处返工拖全批 | 不推荐首轮 |

### D7 · 形态：只读分析，还是允许可执行动作

| 选项 | 影响 | 建议 |
| --- | --- | --- |
| A. 只读 + 存为判断 / 简报 | 不碰写路径，风险最低；用户仍能"把结论留下来" | ✅ 推荐 |
| B. 带催办 / 改期 / 改状态等动作 | 需要每类动作单独过确认与回执；容易变成"第二套操作入口" | 后置到 G3 评估 |

### D8 · 生成通道：Agent 生成落库，还是浏览器直连模型

| 选项 | 影响 | 建议 |
| --- | --- | --- |
| A. 宿主 Agent 调 `workstation` 工具生成 → 落库 → 页面展示 | 工作台**不写模型调用代码**；单一模型入口；可审计 | ✅ 推荐 |
| B. 页面里直接调模型接口 | 需要凭据进浏览器、第二套模型入口（撞宪章八）、无法审计 | 否 |

> **澄清你的问题**："工作台需要 agent 这部分就不需要了" —— 在 A 方案里，工作台**本来就没有 agent 代码**：生成是宿主 Agent 调工作台的工具完成的。所以插件方案省掉的不是"工作台的 agent 代码"，而是"生成这一步归谁"。

### D9 · 依赖：不引 OpenUI / 引 lang-core / 引 React runtime

| 选项 | 影响 | 建议 |
| --- | --- | --- |
| A. 只借架构（模板 + 受控描述 + 本地交互），不引包 | 零新依赖、可导出、可迁移（宪章七） | ✅ 推荐 |
| B. 引 `@openuidev/lang-core` 只做解析校验，渲染器自写 | 多一个依赖与遥测开关；能力更接近 OpenUI Lang | 留作 G4 评估 |
| C. 引 React runtime / browser-bundle（约 900KB gzip） | 引入 React 与构建链，与"零框架、手写 SVG/DOM"冲突 | 否 |

### D10 · 启动时点：W5 收口后，还是立刻并行

| 选项 | 影响 | 建议 |
| --- | --- | --- |
| A. W5 收口后启动 | 发布结论干净；不混批 | ✅ 推荐 |
| B. 立刻并行 | 与"条件性通过、暂不发布"的收尾抢资源，验收口径容易混 | 否 |

### D11 · 架构归属：工作台线，还是宿主 OpenUI 插件线（新增）

| 选项 | 覆盖范围 | 代价 | 建议 |
| --- | --- | --- | --- |
| A. 工作台内渲染（本期 18/27） | 项目 / 知识 / 任务 / 简报等**页面内**视图 | 需要 view 对象 + 渲染器 + 工具动作 | ✅ 本期 |
| B. 宿主 `openui` 插件（另立项） | **对话里**"回答即界面"，不覆盖工作台页面 | 新插件、新发布线、跨插件取数契约 | 另立项，不并入本期 |
| C. 两条线共用 18 号契约 | A 负责数据与保存，B 负责对话内生成/渲染 | 需要先冻结 18 号 | ✅ 方向 |

**B 的可行性（2026-10-18 用宿主 Inspect 实测）**：

- 客户端插槽 `tool.call.toolview` **按 wire Tool 名键、key 域开放**（`open: any string the owner dispatches`）——插件可以给自己的工具注册一个专用视图渲染器；
- 另有 `tool.view.cordis`（键由动态 Client Guard 绑定到本包）可在 `cordis_run` 卡片里渲染交互区域；
- 结论：**"agent 直接有一个 OpenUI 插件"技术上成立**，且不新增模型入口（用户仍然只和同一个 agent 对话）。
- 限制：它只覆盖**对话**，不覆盖工作台页面；工作台要显示生成的视图，仍需要自己的渲染与数据绑定；跨插件取数必须走受控 Service / 工作台工具，不能直读工作台数据库。

## 3 · 架构与数据流（D6–D10 选推荐项时）

```
用户（项目详情 / 知识 / 任务）
   │ 点「生成分析」
   ▼
宿主 Agent ──调用──▶ workstation 工具（新增 action：view.generate / view.save）
   │                         │ 校验 template / params / dataRefs
   │                         │ 只读真实对象（store / graph 同一口径）
   │                         ▼
   │                   返回 view spec（预览，不落库）
   │                         │ 用户点「保存」
   │                         ▼
   └──────────────  draft → 收件箱确认 → 回执可撤销 → kind=view 落库
                             │
                             ▼
                  工作台页面：生成视图渲染器（prototype/generated-view.mjs）
                             │ 只读 + 出处条 + 四态
                             ▼
                  动作：存为判断 / 存为简报 / 打开原对象（全部走现有写路径）
```

**关键约束**：
- 生成与保存分离；不保存的视图关闭即弃，并明说；
- 工作台不直连模型；浏览器不持有凭据；
- `view` 不进入画布、不参与关系派生；
- 视图引用 revision 变化 → `stale` + "依据已变，需复核"。

## 6 · 门禁与验收

**机械**：单测（模板 schema / 校验 / stale / 无损 JSON）；构建后浏览器截图；`npm run verify` 全链。
**语义**：18 号 §8 的 G1–G8，全部带 canary；能机械化的进 `verify`，不能的写成具名人工检查（谁、看什么、什么算过）。
**真实路径**：桌面 5 条 + 手机 3 条；对着**正在运行的实例 + 真实库副本**（WAL 用 `/usr/bin/sqlite3 <db> ".backup <dest>"`）。
**验收单**：按 17 号七关模板写，含"没做什么 / 未验证 / 副作用披露 / 回滚路径"。

## 7 · 风险与回滚

| 风险 | 预防 | 回滚 |
| --- | --- | --- |
| 模型编数 / 编字段 | 渲染前字段映射校验；越界拒绝保存；canary 注入违规样本 | 删除该 `view` 对象 |

## 附录 A · 宿主 `openui` 插件（D11 选项 B，另一条产品线）

**形态**：独立 DSH 插件（不是工作台的一部分）。
- 服务端：注册 `openui` 工具（生成 / 校验 view spec）与受控 Service；
- 客户端：注册 `tool.call.toolview`（键 = 工具名）或 `tool.view.cordis`，在对话卡片里渲染生成界面；交互本地执行，写数据仍经工作台工具 / Agent 回合；
- 数据：只通过工作台的受控工具 / Service 读取，不直读工作台数据库。

**优点**：对话里"回答即界面"；不动工作台冻结的界面；不新增模型入口；可与工作台线共用 18 号契约。
**代价/风险**：新插件 = 新发布线与回滚面；与 DSH 版本耦合；生成内容的视觉规范要另写一份（宿主主题 ≠ 工作台 VI）；同一问题可能"对话里有界面、工作台里没有"，需要说清边界。
**结论**：**不并入本期**；D11 若选 B，单独立项（建议编号 19 规范 / 28 方案），不阻塞 G0–G4。
