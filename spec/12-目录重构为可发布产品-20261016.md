# 目录重构：把工作台做成一个可发布的产品（2026-10-16）

> 用户要求：「我感觉得放在一起，未来整个我要作为一个产品，可以打包，直接到 github 上，
> 不然在我本地电脑是非常凌乱的」。
> 状态：**方案，待你点头后执行**

---

## 1 · 现状的三个真问题（不只是"乱"）

```
~/Desktop/DSH/飞书工作区/     ← 不是 git 仓库
  ├── workstation/       62M   代码        ┐
  ├── spec/              1.2M  代码        ├─ 该进仓库
  ├── design-system/     1.2M  代码        ┘
  ├── workstation-data/  4.5M  **业务数据** ┐
  ├── voice/             251M  **业务数据** ├─ 不该进仓库
  ├── _archive/          80M   **业务数据** ┘
  ├── research/ patches/ 混杂
  └── 个人工作台-PRD-v1.0.md
```

| # | 问题 | 具体后果 |
| --- | --- | --- |
| **1** | **代码目录 == 业务数据根目录** | 同步引擎把 `workstation/` 里的**代码也当成业务文件同步**（实测 5199 个文件里混着大量代码），真正的业务文件变化反而被淹没。**这是"感觉没同步"的一个真实原因** |
| **2** | **在桌面上** | macOS 隐私保护挡住后台任务 —— 定时同步实测报 `Operation not permitted`（退出码 126）。**这是"同步没自动跑"的直接原因** |
| **3** | **没有 git** | 无法版本化、无法打包、无法发布 GitHub；也**没有第二个副本**能防误删 |

## 2 · 目标结构

```
~/DSH/dsh-personal-workstation/          ← 仓库（将来推 GitHub）
  ├── README.md            给人看的说明（怎么装、怎么用）
  ├── LICENSE
  ├── package.json         版本、依赖、脚本
  ├── src/                 插件服务端
  ├── prototype/           界面源码
  ├── client/              客户端插件
  ├── skills/              给智能体的 Skill
  ├── spec/                宪章 / VI / 功能 / 约束（规范本身也是产品的一部分）
  ├── design-system/       色值与图标（VI 的源头）
  ├── test/                测试
  ├── scripts/             安装、同步、体检（从散落各处收回来）
  └── docs/                发布说明、验收记录

~/DSH/飞书工作区/                              ← 业务数据根（**不是仓库**）
  ├── workstation-data/    数据库
  ├── voice/               录音
  ├── _archive/            归档
  └── <各项目文件夹>/       项目材料
```

**为什么要分开**（三条硬理由）：
1. **代码进 git，数据不进** —— 业务数据里有录音、会议纪要、客户信息，**绝不能进公开仓库**
2. **数据移出桌面** —— 后台任务才读得到（解决定时同步的 126）
3. **同步只同步业务数据** —— 不再同步代码，diff 才看得清

## 3 · 迁移怎么做（分三步，每步可回退）

| 步 | 做什么 | 怎么验 |
| --- | --- | --- |
| **① 建仓库** | 在新位置建 `~/DSH/dsh-personal-workstation`，`git init`，把**代码类**目录移过去（`workstation/ src prototype client skills spec design-system test`） | `git status` 能看到文件；`npm run verify` 仍 `EXIT=0` |
| **② 挪数据** | 业务数据留在 `~/DSH/飞书工作区`（**从桌面移出**），改配置里的 `rootDirectory` 与 `dataDirectory` | 工作台能打开、材料能读；两台机器都改 |
| **③ 收脚本** | `sync-now.sh` → 仓库的 `scripts/`；LaunchAgent 指向仓库里的路径 | `launchctl kickstart` 后退出码 **0**，日志有新条目 |

**回退**：每一步之前先 `cp -R` 一份；配置改动只改两行。

## 5 · 这一轮里我顺带发现的两件事（与本方案相关）

1. **同步引擎在同步代码** —— 因为根目录里就是代码。方案落地后自动解决。
2. **定时同步失败的真因是桌面隐私保护**，不是脚本写错（脚本手动跑 `EXIT=0`，5199/5199 文件一致、19/19 对象一致）。方案第 ② 步解决。
