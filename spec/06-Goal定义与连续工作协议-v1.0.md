# 个人工作台 · Goal 定义与连续工作协议 v1.0

用途：把四份冻结基线变成**一个能连续跑几十小时不跑偏的目标**。
依据：[01 宪章](01-顶层宪章-v1.0.md) · [02 VI](02-VI规范-v1.0.md) · [03 功能与交互](03-功能与交互设计-v1.0.md) · [04 规划与约束](04-开发规划与约束-v1.0.md) · [05 现状评估](05-现状评估与改造清单-v1.0.md)

## 1 · 什么叫"符合 goal 的目标"

一个能连续工作的目标必须同时满足四条。缺任何一条，几十小时后必然跑偏：

| 判据 | 含义 | 反例（会跑偏的写法） |
|---|---|---|
| **可验收** | 完成判据能**机械验证**：门禁脚本 + 真实浏览器证据 | "把工作台做得更好用" |
| **可分割** | 能切成互不依赖的批次，**任一批停下都不留半成品** | "重构后端" |
| **有停止条件** | 明确什么算完成、什么算阻塞、什么必须问人 | "持续优化" |
| **能连续** | 每轮产出可交接（账本 + 证据路径），**不依赖上下文记忆** | "接着上次继续" |

> 一句话：**目标要能被别人（或下一轮的你）在没有上下文的情况下接着做。**

## 2 · 目标定义（可直接用于 goal）

> **按 spec/01–05 五份冻结基线，把 `dsh-personal-workstation` 从 1.10.0 改造到符合宪章：完成批次 0–6（护栏 → 判断 F6–F9 → 待核对 F7 → 建议闭环 F10–F14 → VI 收敛 V1–V9 → 拿出 F15–F18），每批通过其验收判据与 12 项 VI 门禁，并留下账本与真实浏览器证据；心跳（F19–F24）作为**有条件后续**，只在常驻节点可用时进行。**

**为什么这样界定**：

- 把心跳（批次 7–8）划为"有条件后续"—— 它有真实外部依赖（常驻节点、飞书发送接口），放进主目标会让目标在等外部条件时空转；
- 把终验（批次 9）保留在主目标内 —— 它是"符合宪章"的最终判据，不能省。

## 3 · 完成判据（DoD，全部可机械验证）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 批次 0–6 逐批验收通过 | 每批的验收标准（见 04 §3）逐条有证据 |
| 2 | VI 12 项门禁全绿 | `verify` + `audit:craft` 全绿（含字面色值 = 0、`!important` = 0、标尺外间距 = 0、组件唯一、四态齐全） |
| 3 | 03 文档十条验收判据通过 | 逐条给出真实数据 + 真实浏览器证据 |
| 4 | 界面词汇零新增 | `registry.json` 校验通过；禁造词扫描为 0 |
| 5 | 每批有账本 | 账本含"改了什么 / 没做什么 / 证据路径"，**缺"没做什么"不算** |
| 6 | 已发布并核实运行版本 | 装包 → 重启 → **实测运行版本**（"安装成功 ≠ 已加载"） |

**反目标 —— 以下都不算完成**：

- 单测通过但界面上点不到（历史教训：元素在 DOM 里但渲染在可视区外）；
- 记录在非默认页签里（"知识页默认研究议题，材料在文件与资料"）；
- 主动作跳到别处（该原地展开却跳页）；
- 绕过门禁（用 `!important`、写死色值、把新词塞进代码）；
- 账本只写"已完成"而没有"没做什么"；
- 只有文档没有代码，或只有代码没有证据；
- 声称"已加载"而未实测运行版本。

## 4 · 轮次与预算

| 项 | 值 |
|---|---|
| 单批工作量 | 2–4 小时 |
| 建议 `max_goal_rounds` | **30 轮**（8 个批次 × 平均 3 轮 + 终验与返工余量） |
| 每轮产出 | 至多**一个批次**的推进；**不跨批混改** |
| 对齐自检 | 每完成 **3 批**一次 |

---

## 5 · 连续工作协议

### 每轮开工（固定顺序，不得跳步）

1. 读 `spec/04` §3 中**本批**那一条 —— 确认依据、范围、验收、不做；
2. 读最近 **3 条**账 —— 确认上一批真的收口了；
3. 读 `spec/01` 宪章标题九条 —— 校准立场（防止被实现细节带偏）；
4. 确认存在备份点、工作区干净。

### 每轮收工（固定格式，五行以内）

```
本批：批次 N
改了什么：<逐条，最多 5 条>
没做什么：<必须写，哪怕是"没有>
证据：<门禁输出路径 / 截图路径 / 账本路径>
下一批第一件事：<一句话>
```

**为什么强制"没做什么"**：这是唯一能防止"看起来做完了"的字段。历史上多次出现"功能写完但界面上找不到"。

### 每 3 批一次对齐自检（三个问题）

1. 这 3 批里有**新造的词**吗？（查 registry 与禁造词表）
2. 有**绕过门禁**的地方吗？（查 `!important`、字面色值、标尺外间距）
3. 有**超出宪章依据**的功能吗？（每个改动能否指回 F 编号 + 宪章条文）

任一条为"是"→ 停止推进，先修。

## 6 · 停止与上报条件

| 情况 | 动作 |
|---|---|
| 批次 0–6 全部通过且 DoD 六条满足 | `update_goal` → **complete** |
| 同一阻塞连续 **3 轮**无法推进 | `update_goal` → **blocked**，写明具体条件 |
| 命中"偏离即停"8 条任一（见 04 §4） | **停止编码**，按固定格式上报：现象 → 证据 → 可选方案（≥2）→ 建议 → 影响面 |
| 需要外部凭证/设备（常驻节点、飞书接口） | 不阻塞主目标：跳过批次 7–8，继续推进可做部分，并如实标注"未接入" |

**不允许**：为了让进度好看而把未完成写成已完成；把"接口已规划"写成"已经能用"；在门禁红的情况下进入下一批。

## 7 · 与批次计划的对应

| 轮次区间（建议） | 批次 | 里程碑 |
|---|---|---|
| R1 | 批次 0 护栏 | **M0**：守卫脚本能报出真实违规数（预期：字面色值 258、`!important` 19、标尺外间距 ≥3） |
| R2–R5 | 批次 1 判断 | **M1**：一条真实会议判断能被沉淀、追溯、复核、推翻留痕 |
| R6 | 批次 2 待核对 | M1 收口（入口数不变） |
| R7–R11 | 批次 3 建议·数据 | **M2**：建议生命周期跑通，否决理由被记住 |
| R12–R15 | 批次 4 建议·界面 | **M3**：零跳页完成四回应，"为什么这么建议"可展开 |
| R16–R21 | 批次 5 VI 收敛 | **M4**：12 项门禁全绿 —— 这是本目标最硬的一道门 |
| R22–R25 | 批次 6 拿出来 | **M5**：判断可导出、可分享、默认仅自己 |
| R26–R30 | 批次 9 终验 + 返工 | **M6**：DoD 六条全满足，发布并核实运行版本 |

## 8 · 一页速记

> **目标**：1.10.0 → 符合宪章（批次 0–6）。
> **判据**：门禁全绿 + 十条判据 + 零新增词汇 + 每批账本 + 核实运行版本。
> **节奏**：每轮一批；开工四步；收工五行；每三批自检。
> **停止**：做完 complete；同一阻塞三轮 blocked；偏离即停先问人。
> **不变的四句**：依据不明确的不做；入口不动；词汇不增；未接入不装。
