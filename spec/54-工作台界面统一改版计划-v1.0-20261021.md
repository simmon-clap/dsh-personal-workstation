## 0 · 三句话

1. **分类不能照搬四极**：四极是天宽价值网的压缩模板；通用规则是「按相对当前焦点的关系角色分类」，项目不同、角色不同，用模板 + 参与者角色解决。
2. **点击组织不换页**：就在原位置展开/收起项目和任务，镜头放大到那一块；双击才开详情弹窗；没有新页面、没有路由跳转。
3. **项目/任务/收件箱统一**：同一套卡片、筛选、详情弹窗、编辑差异、状态、空态、手机规则；不新增入口，不丢现有功能。

## 1 · 分类判断：四极是模板，不是通用分类

### 1.1 四极为什么不能直接推广

| 四极 | 实际包含 | 为什么不能直接套到别的项目 |
|---|---|---|
| 核心 | 天宽自己 | 其他项目不一定是「一个主体 + 四个极」，也可能没有中心 |
| 势能极 | 国家实验室、政策、公共机构 | 别的项目可能是客户、监管、资助方，含义不同 |
| 供给极 | 芯片/算力/基础设施 | 交付项目里可能是分包商、外包团队 |
| 价值极 | 模型厂商 + 应用/具身厂商 + 客户场景 | **把「客户」和「伙伴」压成了一类**，换项目就不成立 |
| 规则极 | 标准组织、行业联盟 | 研究项目里可能是同行评议、发表渠道 |

结论：四极是**天宽生态/战略视角下的自定义模板**，不是产品默认分类。

### 1.2 判断：按「相对焦点的关系角色」分类

**焦点** = 这张画布正在回答「谁围绕谁」：
- 全部机构视图：焦点是「我/我的组织」（或用户选的主体）
- 项目视图：焦点是「这个项目」
- 议题/研判：焦点是「这个标的/议题」

**通用角色**（默认 8 类 + 其他）：

| # | 角色 | 判断标准 | 典型对象 |
|---|---|---|---|
| 1 | 主体 / 自身 | 谁在做事、谁承担结果 | 我的组织、项目组、体外公司 |
| 2 | 客户 / 需求 | 谁为结果买单、谁使用结果 | 甲方、业主、使用方 |
| 3 | 伙伴 / 协作 | 共同交付、共同承担、联盟 | 联合方案、渠道伙伴、生态伙伴 |
| 4 | 供应 / 交付 | 提供技术、设备、算力、分包 | 芯片、云、集成商、外包 |
| 5 | 研究 / 政策 | 提供合法性、政策、研究能力 | 国家实验室、政策部门、高校 |
| 6 | 标准 / 行业 | 定规则、做认证、行业组织 | 标准组织、协会、检测机构 |
| 7 | 资本 / 渠道 | 出钱、导流、撮合 | 投资方、基金、渠道商 |
| 8 | 竞争 / 替代 | 抢同一预算或同一场景 | 竞争对手、替代方案 |
| 9 | 其他 / 未分类 | 暂时判断不了 | 未建档、待确认 |

**为什么这是通用判断**：
- 角色是**关系**，不是组织固有属性；同一机构在 A 项目是客户、在 B 项目是伙伴，符合现实。
- 8 类覆盖了「谁买单、谁一起干、谁供货、谁给合法性、谁定规则、谁给钱、谁抢生意」——任何项目都能落进去。
- 颜色/形状只做编码，不改变角色含义。

### 1.3 天宽四极怎么映射到通用角色

| 四极 | 映射到通用角色 | 说明 |
|---|---|---|
| 核心 | 主体 / 自身 | 天宽自己 |
| 势能极 | 研究 / 政策 | 国家实验室、政策、公共机构 |
| 供给极 | 供应 / 交付 | 芯片、算力、基础设施 |
| 价值极 | **客户 / 需求 + 伙伴 / 协作** | 四极把两类压成一类；通用模型要拆开 |
| 规则极 | 标准 / 行业 | 标准组织、行业联盟 |

所以：
- 天宽生态图 = **主体 + 研究政策 + 供应 + 客户/伙伴 + 标准** 的压缩展示；
- 换成别的项目，用通用角色/模板重新组合即可；
- 演示里的四极保留为「天宽示例模板」，不是产品默认。

### 1.4 其他项目按什么类别：按项目类型选模板

不给所有项目硬套一套分类；给**模板 + 可改**。推荐四个模板：

| 项目类型 | 推荐分类（按顺序） | 为什么 |
|---|---|---|
| 客户交付 | 我方、客户、伙伴、供应/分包、监管/标准、其他 | 交付项目最关心「谁验收、谁一起干、谁供货」 |
| 生态/战略 | 主体、研究/政策、供应/基础设施、客户、伙伴、标准、资本、其他 | 天宽四极落在这里；可按需压缩 |
| 研判/投资 | 标的、技术供应、客户场景、资本、政策、竞争、其他 | 判断「这个标的值不值得」的关键角色 |
| 研究议题 | 证据来源、同行、反方、资助、标准、其他 | 研究最关心「证据、同行、反证、谁出钱」 |
| 自定义 | 用户自己定 | 不强迫 |

**怎么选**：
- 新建项目时按项目类型/字段**建议**一个模板（不是自动套用）；
- 项目详情里可改模板；改模板只改「分类视图」，不改组织记录；
- 没有项目上下文时，用通用 8 类，默认「未分类」。

**AI 可以做什么**：从项目名称/材料/已有关系**建议**角色（带依据），但**不自动写入**；用户确认后才成为参与者角色。符合宪章三/四/五、17 C7。

### 1.5 数据模型：全局默认角色 + 项目参与者角色

| 位置 | 字段 | 含义 |
|---|---|---|
| organization | `defaultRole`（新字段；53 里的 `category` 改名） | 全局视图里这个机构的默认角色；可空=未分类 |
| project | `roleTemplate` | 模板键：delivery / ecosystem / investment / research / custom |
| project | `participants: [{organizationId, role}]` | 本项目里这个机构扮演的角色；同一项目同一机构只一条 |
| project | `partnerId`（保留） | 兼容旧数据；迁移时映射为 participants 的一条 |
| layout:ecosystem | `roleColors / roleShapes / order` | 角色到颜色/形状/顺序的视觉映射；不存第二份角色名 |
| 画布 | `scope: all / project:<id>` | 全部按 defaultRole 分组；项目按 participants.role 分组 |

- 角色名唯一事实源：`organization.defaultRole` 与 `project.participants[].role`；`layout` 只做视觉映射。
- 一个机构在同一项目只能有一个角色；跨项目可不同。
- 未归属/未分类如实显示，不猜。
- 四极模板不写进产品代码；演示数据/用户自定义里才有。

### 1.6 产品默认 vs 示例

| | 产品默认 | 演示 |
|---|---|---|
| 分类词 | 通用 8 类 / 模板 | 天宽四极 |
| 主体 | 用户自己的组织；可没有 | 天宽 |
| 模板 | 交付/生态/研判/研究/自定义 | 天宽生态（自定义模板） |
| 代码 | 无天宽专用词（定位门禁） | 示例数据可含 |

## 2 · 展开交互：原地放大，不换页

### 2.1 现在演示的问题

演示页点击机构会**换成一个聚焦链条**（只显示机构→项目→任务），看起来像跳到了另一个视图。
这不符合用户要求：**应在原位置展开，镜头放大到那一块，不换页。**

### 2.2 目标行为

| 动作 | 行为 |
|---|---|
| 单击机构 | 在原位置展开它的项目（卡片从机构旁边长出）；镜头动画放大到「机构 + 项目」；其他节点保留但变淡；**不换页、不改路由** |
| 再次单击机构 / Esc | 收起项目与任务；镜头回到展开前 |
| 单击项目 | 在项目旁边展开任务；镜头微调；不换页 |
| 双击机构/项目/任务 | 打开居中详情弹窗（现有弹窗） |
| 单击另一机构 | 收起上一个分支，展开新分支（一次只展开一个，避免版面爆炸） |
| 全图 | 工具条「全图」回到全局；不离开画布 |
| 低缩放 | 子节点折叠为「N 个项目 / N 个任务」计数；放大后再展开 |

### 2.3 布局与镜头

- 子卡片方向：从机构向**远离画布中心**的方向长（左半区向右、右半区向左、上半区向下、下半区向上）；空间不够时优先向空的一侧。
- 项目卡：机构旁一列；任务卡：项目旁一列；连线实线。
- 镜头：`fitRect(机构+子节点)`，动画 220ms、位移 ≤8px；不缩放超过 1.0，不低于 0.6。
- 碰撞：子节点与其它卡重叠时，子分支提升层级、其它节点淡化；不移动用户原有节点位置（避免"点一下全图重排"）。
- 展开状态：v1 只存在本次会话，不写业务数据；后续可存 layout。
- 画布仍保留平移/缩放/框选/分组/预览/导出/撤销/关系筛选；结构态只是新增一种分组呈现。

### 2.4 验收

- 点击机构后 URL/路由不变；页面不白屏、不重建；其他节点仍在 DOM/画布上。
- 镜头确实放大到该机构与子节点；再点收起；Esc 收起。
- 双击开详情；详情关闭后展开状态还在。
- 1440/390 都能用；390 首屏可操作。

## 3 · 项目 / 任务 / 收件箱统一

### 3.1 统一什么（不新增入口）

| 层 | 统一规则 |
|---|---|
| 页面框架 | 面包屑 + 页面标题 + 一句真实提示 + 一个主色动作；沿用现有 shell，不新增顶栏 |
| 模式切换 | 同一套分段控件；项目（组合/路线/名册）、任务（看板/依赖）、收件箱（状态筛选）都用它 |
| 筛选 | 全站唯一「筛选」按钮 + 面板（现有 `filterBarHtml`）；默认不显示「筛选 · 1」 |
| 卡片 | 一套卡片组件，两档密度：页面标准档（内边距 20/24）、画布紧凑档（登记为画布节点变体） |
| 详情 | 一套居中弹窗：标题行、元信息、正文、动作区 ≤2；760 宽（VI §6） |
| 编辑 | 一套「编辑」模式：字段缓冲、差异条、只改改动项、保存后撤销、未保存保护 |
| 状态 | 一套状态点/文字/标签；颜色不单独承担判断 |
| 空态 | 一套简笔画 + 一句状态 + 一个下一步；空数据不画图 |
| 反馈 | 一套「已保存/已改 · 撤销」Toast；失败一句人话 + 下一步 |
| 手机 | 390 首屏至少 1 个可操作内容；详情决定字段不被底栏遮挡 |
| 动效 | 120/180/220ms；位移 ≤8px；无装饰动效 |

### 3.2 项目页

- **PJ-01 组合/路线图**：保留两视图；组合页**一张项目卡只出现一次**（现在卡片 + 交付条重复表达同一项目）。
- **PJ-02 详情**：伙伴/交付比例/剩余/阻塞/资料/任务/阶段保留；统一详情弹窗。
- **PJ-03 阶段**：接触/需求/方案/验证/复盘保留；阶段与交付比例分开。
- **PJ-04 联动**：任务/画布/资料入口保留。
- **改**：卡片紧凑化（标题、阶段、负责人、截止、任务数、真实交付进度）；无交付项不画空进度条；「交付与阻塞分布」只在有数据时出现，或并进卡片/详情，避免重复。
- **验收**：两张项目卡首屏可见；点开详情能编辑并只存改动；空交付不画图。

### 3.3 任务页

- **TK-01 看板**：等待/运行/完成（真实状态）保留；空列折叠。
- **TK-02 步骤比例**：有步骤才算比例；0/0 不画环。
- **TK-03 依赖**：保留依赖视图；等待原因/输入/输出可见。
- **TK-04 新建**：名称/项目/执行位置/输入/预期输出保留。
- **TK-05 助理**：来源与行动项保留。
- **改**：卡片紧凑化（标题、项目、状态、负责人、截止、步骤进度、等待原因）；去掉占半屏的单个大数字；首屏能看到多列/多条；手机首屏至少 1 条任务。
- **验收**：1440 首屏 ≥2 列可见；390 首屏 ≥1 条可操作；详情编辑只存改动。

### 3.4 收件箱

- **CH-04 列表**：状态筛选、来源/项目/类型筛选、空态、已处理不重复提醒保留。
- **建议四回应**：采纳/改写/否决/稍后 + 理由 + 为什么不重复推荐，保留。
- **改**：卡片减密（标题、变更摘要、差异条、来源/时间、主动作）；详情用统一弹窗/差异组件；去掉「最近加载 N 条」这类实现说明；默认筛选不显示「筛选 · 1」；AI 建议与普通改动同一卡片结构，但来源标识不同。
- **验收**：一条改动能展开看差异后同意；不同意不消失且记理由；空态一句人话 + 下一步；手机可操作。

### 3.5 对照 VI 与功能规范

### 3.6 不做什么

- 不把项目/任务/收件箱改成画布
- 不改 7 视图的信息架构

- 不把 AI 推断当事实；不自动分类/自动改结构

## 4 · 共享组件与门禁

| 组件 | 要求 | 门禁 |
|---|---|---|
| 卡片 | 一套实现，标准/紧凑两档；圆角 12；边框 1px | 组件签名唯一；画布节点变体已登记 |

## 附录 A · 四极到通用角色的映射（一句话）

**四极 = 主体 + 研究政策 + 供应 + 客户/伙伴（合并）+ 标准**。
所以它适合天宽生态，不适合所有项目；通用做法是拆成「关系角色」，用项目模板组合。

## 附录 B · 三页统一后长什么样

- **项目**：一张项目卡 = 名称、阶段、负责人、截止、任务数、真实交付进度；点开详情编辑；不再重复画交付条。
- **任务**：看板卡 = 名称、项目、状态、负责人、截止、步骤进度；无步骤不画环；点开详情编辑。
- **收件箱**：改动卡 = 标题、变更摘要、差异条、来源/时间、主动作；展开差异后同意/不同意；AI 建议同一结构、来源不同。
