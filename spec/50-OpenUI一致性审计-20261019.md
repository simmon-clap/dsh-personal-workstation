## 0 · 审计口径

### 0.1 “按 OpenUI 实现”的判定标准

| 层级 | 判据 | 本审计怎么查 |
| --- | --- | --- |
| L1 组件名 | 官方注册名是否在 DSH 目录 | `openuiLibrary.tsx` / `openuiChatLibrary.tsx` 的 `createLibrary({components})` |
| L2 组件签名 | 位置参数、必填项、slot 类型、上限是否与官方 schema 一致 | 官方 `*/schema.ts` vs `src/catalog.mjs` / `src/kit.mjs` |
| L3 组件行为 | 官方组件的交互/降级/加载态是否实现 | `src/renderer.mjs` + 单测 + 真实实例 |
| L4 语言效果 | OpenUI Lang 的 22 条能力是否可运行 | 官方 docs + 本地包源码；DSH `kit.mjs` / `client-entry.mjs` |
| L5 验收 | 机械门禁 + 真实实例 + 双端 + 可复现 | `node --test`、`acceptance/live-check.mjs`、账本 |

> 本审计只判 **组件/行为/语言效果**，不做 OpenUI 官方 CSS 的像素级比对；视觉是另一条线（见 §7.4）。

### 0.2 参考基准的边界

- 官方两个库：general `openuiLibrary` 82 个、chat `openuiChatLibrary` 84 个；去重 **86** 个（chat 多 `FollowUpBlock`、`FollowUpItem`、`SectionBlock`、`SectionItem`；general 多 `Stack`、`Modal`）。
- 官方“效果”是 **OpenUI Lang 运行时能力**，不等于组件自带的 hover/过渡动画；本审计按 E01–E22 核对。
- 如果用户说的“OpenUI”是另一份组件清单（不是 `@openuidev/react-ui`），本审计的参照系需要替换；目前证据只能支持这一份。

## 6 · 当前实现的硬缺陷与漂移（本次实测）

### 6.1 机械门禁未全绿：CSS 硬编码颜色（而且是两层红）

- 命令：`node --test test/*.test.mjs` → **40 pass / 1 fail**。
- 第一层失败：`test/renderer.test.mjs:515`「颜色必须是 token，不允许十六进制色值」。
- 根因：`src/renderer-css.mjs:683` `box-shadow: inset 0 1px 0 color-mix(in srgb, #fff 35%, transparent);`
- **第二层（被第一层挡住）**：修掉 `#fff` 后，`test/renderer.test.mjs:517-519` 会因 10 个 `--oui-*` 局部变量不在 `ALLOWED_TOKENS` 而继续红（`--oui-action` / `--oui-danger` / `--oui-surface` / `--oui-grad-soft` / `--oui-line` / `--oui-ink` / `--oui-glass` / `--oui-grad` / `--oui-success` / `--oui-warning`）。
- 说明：0.2.0 的 Paper Glass 适配层（2026-10-18 16:56 加入）在当前 `ALLOWED_TOKENS` 下不可能通过；21 号账本里的 41/41 是加视觉层之前的记录（14:03/14:38），不能证明当前层通过。
- 影响：违反 19 号 §5.2「不写字面色值」；当前构建产物包含该颜色，暗色/主题模式下可能不一致。
- 证据：`command-evidence.txt`；`dsh-implementation.md` §2.2。

### 6.2 真实实例手机 390 溢出 6px

- `acceptance/live-check.mjs`：7 PASS / 1 FAIL；FAIL「手机端无横向溢出 → overflowX=6」。
- 定位：3 个 `.oui-field.oui-field-select`（「最想补的场景组件」「配色偏好」「信息密度」）宽度 257，右边界 269，超出卡片 263 **6px**；隐藏 `.oui-form` 后溢出消失；隐藏 table/tabs/gallery/chart/timeline 均无变化。
- 影响：违反 19 号 §5.7 / G6「390 无横向溢出」；真实手机宽度下卡片可横向拖动。
- 证据：`live-check.md` §七。

### 6.3 turnTail 主呈现面：CSS 作用域错误 + 观测属性缺失 + 失败态缺失（用户可见）

**这是当前最严重的用户可见缺陷，且 live-check 抓不到。**

- `TurnTailCard` 的根节点是 `.oui-turn-card`（`src/client-entry.mjs:197`），但 Paper Glass 的 10 个 `--oui-*` 变量、盒模型 reset、焦点环都只定义在 `.oui-root` 下（`src/renderer-css.mjs:651-663`、`:562-573`）。turnTail 没有 `.oui-root` 包裹。
- 2026-10-19 09:19 只读 Puppeteer 探针（真实卡片，非夹具）：
  - `getComputedStyle(card).getPropertyValue('--oui-grad')` = **空串**；`--oui-action` / `--oui-surface` / `--oui-glass` 同样为空；
  - `.oui-stat-value`（如“组件总数 21”的数字）：`color = rgba(0, 0, 0, 0)`、`background-image = none`、`-webkit-background-clip = text` → **数字不可见**；
  - `.oui-button-primary`（“提交反馈”）：`color = rgb(255, 255, 255)`、`background-color = rgba(0, 0, 0, 0)`、`background-image = none` → 白字透明底，**按钮文字不可见**；
  - `.oui-card`：`background-color = rgba(0, 0, 0, 0)`、`border = 0 none`、`box-sizing = content-box` → 卡片表面/边框/reset 同样失效；
  - 焦点环 / 盒模型 reset 同样不生效。

## 7 · 为什么“全量按 OpenUI”不是补几个组件

### 7.1 语言不兼容

- 官方：位置参数 `Card([...])`、`TextContent("...")`、`Table([Col(...)])`、`$变量`、`@函数`、`Action([...])`；
- DSH：对象参数 `Card({children:[...]})`、`Text({text:'...'})`、`Table({columns,rows})`，没有表达式/变量/函数。
- 两者只是“行式语言 + 白名单 + 渐进渲染”架构相似；**不是同一语法**。要让 DSH 源码按 OpenUI 写，必须换语言版本（旧界面源码会全部失效，需要迁移/重放策略）。

### 7.2 效果是运行时，不是样式

- E02/E04/E06/E07/E08/E09/E10/E19 等需要表达式求值、状态、函数、Query/Mutation、工具提供方、动作步骤；
- 当前渲染器只做“纯数据节点 → React 元素”，没有求值器；补齐等于重写 OpenUI Lang 运行时（或引入官方运行时）。

### 7.3 与 DSH 已冻结的安全/VI 边界冲突

| 冲突点 | 19 号当前约束 | OpenUI 全量能力 |
| --- | --- | --- |
| 写操作 | 不执行写操作、只 send/open（§1.2/§3.3） | `Mutation` + `@Run` + 自定义 action |
| 网络/取数 | 不调外部工具、不请求网络（§1.2/§4.1） | `Query` + `toolProvider` + 自动刷新 |
| 第二模型入口 | 不调模型、只有一个界面入口（§1.2/§4.4） | `@ToAssistant` 可回灌模型 |
| 图标 | 不用 emoji、不提供图标组件（§1.2） | `Icon`（lucide）+ IconButton/IconText 等 |
| 数据诚实 | 不编数、无来源写“未知/待确认”（§4.3） | 官方示例规则含 “generate realistic/plausible data” |
| 视觉 | 只用宿主 `--dsw-alias-*` + Paper Glass（§5） | 官方自带组件 CSS/主题 |

> 结论：要“所有组件和所有效果”，必须**改 19 号冻结条款**（并可能触及宪章八/VI），不是单纯写代码。哪些效果允许、哪些禁止，需要用户拍板。

### 7.4 视觉“效果”与组件“效果”是两件事

- 如果“效果”指 OpenUI 官方组件的视觉/动效：需要放弃/改写 Paper Glass 与宿主 token 的约束；与 02 号 VI、Paper Glass v1.0 冲突。
- 如果指交互/语言效果（本审计口径）：与 §7.3 的边界冲突。
- **2026-10-19 用户拍板：视觉锁定 Paper Glass，不要求与官方像素一致；OpenUI 只作为组件/行为/语言参照。** 这一条不再作为决策门；后续实现只使用 `design-system/paper-glass/` 的 token/组件/材质/渐变，不引官方 CSS。

## 8 · 若要“后面都按 OpenUI 实现”：建议的契约与路线

### 8.1 先定“完成”的合同

建议新增 `openui-conformance.json`（86 组件 + 22 效果）：
`{name, source, group, dsh, status: exact|partial|missing|rejected, evidence, owner, tests}`。

规则：
1. **先改映射表，再改代码**；没有映射的组件/效果不允许出现在提示词与目录里。
2. 每次组件目录变更 = 语言版本变更：更新映射 + 提示词快照 + 门禁 + 账本。
3. 对外只能说 `exact` 的部分；`partial/missing/rejected` 必须列在“未实现”清单里。
4. 版本钉死：`@openuidev/react-ui@0.18.1`、`@openuidev/react-lang@1.0.1`；升级先跑差异审计。

### 8.2 三条路线（视觉已定；路线仍需用户选）

> **已拍板（2026-10-19）**：视觉按 Paper Glass，不追求与 OpenUI 官方像素一致。因此 A 路线 = **官方 OpenUI Lang 运行时 + Paper Glass 组件实现/主题**，不引官方 `react-ui` 的 CSS；B/C 同样以 Paper Glass 为唯一视觉层。

| 路线 | 做法 | 成本/风险 | 适用 |
| --- | --- | --- | --- |
| **A. 接入官方运行时**（推荐先做 1–2 天 spike） | 在 Client 插件里预打包 `@openuidev/react-lang`（解析/状态/函数/动作），用 `defineComponent` 写 **Paper Glass 组件库**（可保留 Map/Timeline 等 DSH 自有组件）；不引官方 `react-ui` CSS；DSH 自己写提示词与安全过滤；React 18.3.1 已满足 peer | 依赖体积、slot/样式映射、官方 API 版本风险；Query/Mutation/自定义 action 必须按 §7.3 禁用或另批；86 个组件的 Paper Glass 视觉仍需逐个实现 | 想要“全量组件 + 效果”，视觉仍 Paper Glass |

| **C. 锁定“OpenUI 兼容子集”** | 冻结 20–30 个组件（建议优先官方同名/高频：Card/Text/Table/Tabs/Form/Buttons/Charts/List/Tag/Modal/Accordion），把名字/签名逐步对齐；明确 deviation ledger；不声称全量 | 最小可交付；但“所有组件/效果”仍不成立 | 先上线、后扩 |

**我的建议**：先做 **A 的 spike** 验证官方运行时能否在 DSH 的 Client 插件/主题/`render_ui` 链路里跑通；同时用 **C 的口径**对外（只承诺子集）。若 spike 失败再回到 B/C。

### 8.3 不管选哪条，先补的门禁

1. **turnTail 作用域**：把 `.oui-root` 的变量/reset/焦点环作用到 `.oui-turn-card`（或给 turnTail 加 `.oui-root` 包裹）；修 `Stat` 数值透明、主按钮白字透明底。

3. `node --test` 全绿：`#fff` + 10 个 `--oui-*` token 白名单；`test/build.test.mjs` 真重建；`test/prompt.test.mjs` 落地；`test/gates.test.mjs` / `acceptance/gates.mjs` 建起来。

5. 构建 sha256 与账本同步；每次改动先记账；旧 live-check 报告标注“不可用于当前构建”。
6. OpenUI 映射表 + 组件/效果门禁（至少“目录↔映射↔提示词”三方一致）。
