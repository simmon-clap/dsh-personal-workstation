## 1 · 目标与完成判据

**目标（三句话）**：真实对话里 Agent 能生成三类界面——行程/路线、方案对比、表单收集；生成过程按三阶段渐进出现；界面里的按钮真的把文本发回会话、链接真的按规则打开；桌面 1440 与手机 390 都能用，重放/fork 能重建。

### 1.1 算完成（缺一条都不算）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| 1 | **真实实例** | 宿主 **0.2.1-rc.2** + desktop profile + 已装 `dsh-intelligent-ui` bundle（本机实测），不是测试桩、不是假 slot |
| 2 | **真实数据** | 真实对话、真实工具结果；界面内容来自会话上下文，不用内存夹具或脚本注入的假回答代替 |
| 3 | **双端** | 桌面 1440 + 手机 390 各至少 3 张截图（生成中 / 完成 / 失败态） |
| 4 | **语义门禁** | 19 号 G1–G8 全绿，且每条 canary 都证明会红；机械门禁 + 人工检查单各有签字人 |
| 5 | **交互回执** | 至少 4 条真实动作：按钮发送、快捷建议、表单提交、外链打开；发送后能在会话里看到新用户消息 |
| 6 | **可复现** | 同一 Session 重放 / fork 后节点数、根类型、错误数一致；旧源码含未知组件时降级不崩 |
| 7 | **账本** | 做了什么 / 没做什么 / 证据在哪 / 不确定性 / 副作用披露 / 回滚路径，六项齐全 |
| 8 | **可卸载回滚** | 卸载 bundle 后宿主恢复正常（工具卡片回落通用卡、无报错），回滚步骤可复现 |

### 1.2 不算完成

- 单测通过、`node --test` 全绿、门禁全绿——**只证明在标尺内，不证明界面能用**（17 C3）；
- 只有截图没有门禁；只有门禁没有真实对话；
- 用 `compileUi` 直接喂源码渲染出的"界面"（夹具），不是 Agent 在真实对话里生成的；
- 元素在 DOM 但不可见、按钮点了没反应、发送按钮只改本地 state；
- 门禁 skip 当通过、canary 没红过、假绿未修；
- 只写"已安装/已完成"，没有卸载与单文件回滚路径。

## 2 · 决策门 D12–D16（先拍板，后动工）

> 拍板方式：逐条回"同意推荐"或写选择。**未拍板前，对应分支不实现**；不影响 P0 的门禁骨架。

### D12 · 是否引入 OpenUI 运行时

| 选项 | 影响 | 判断 |
| --- | --- | --- |
| **A. v1 不引运行时，只借架构**（行式语言 + 白名单 + 渐进渲染，解析器自写） | 零新依赖；与 React 18.2 兼容；可迁移（宪章七） | ✅ **推荐** |
| B. 只引 `@openuidev/lang-core` 做解析/校验 | 多一个依赖与遥测开关；能力更接近 OpenUI Lang；解析器仍要适配 18.2 | 留作 P4 后评估 |
| C. 引 `@openuidev/react-lang` 官方运行时 | 官方 peer 依赖 `react>=19`，宿主是 18.2；要么升级宿主 React、要么锁死版本，风险与成本最高 | 否 |

**推荐理由（事实）**：官方 `@openuidev/react-lang` 的 peer 依赖是 `react>=19`，DSH 0.2.1-rc.2 客户端是 React 18.2；许可 MIT 不构成障碍，**版本才是**。v1 只借"行式语言 + 白名单组件 + 渐进渲染"三项架构，不引包、不引构建链。

### D13 · 是否允许 `open` 外链

| 选项 | 影响 | 判断 |
| --- | --- | --- |
| **A. 允许但受限**：只 http(s)；用户点击才打开；`noopener,noreferrer`；不预取/不预览/不代理 | 地图/引用/文档可点；风险在有来源的真实性（由提示词 + G7 人工检查兜） | ✅ **推荐** |
| B. 完全禁止 `open`，只保留 `send` | 最安全，但行程/引用类界面失去"点开看原文"的出口，用户回到复制粘贴 | 可作保守回退 |
| C. 允许任意 scheme / 相对路径 | 直接违反 19 §4.2；`javascript:` 注入面 | 否 |

**推荐理由**：用户要的是"回答即界面、能点下一步"；`open` 是两类动作里唯一对外动作，受限开放比完全禁止更符合人机分工（宪章五）。失败回退是 D13-B（一处开关，不加功能）。

### D14 · 地图瓦片与离线策略

| 选项 | 影响 | 判断 |
| --- | --- | --- |
| **A. v1 不用真实瓦片**：`Map` 只画本地几何（网格底 + `markers` + `route` 折线 + 说明"示意图"），不请求第三方 | 零网络依赖、零隐私外泄、离线可用；不能当地图导航用，需在 UI 文案里标明 | ✅ **推荐** |
| B. 接在线瓦片（OSM/高德等） | 第三方域名、隐私（用户位置）、离线不可用、许可与配额、还要处理瓦片失败态 | 留 P4 后评估 |
| C. 从语言白名单移除 `Map` | 最省事；但行程类回答少一个自然组件 | P2 兜底方案（A 做不出来时用） |

**推荐理由**：v1 的诚实底线是"不编地点、不假装有地图能力"；本地几何足够表达"顺序与位置关系"，且不引入新的外部服务与凭据（13 §4 能力可选接入）。

### D15 · 是否把对话界面写入工作台 `view` 对象

| 选项 | 影响 | 判断 |
| --- | --- | --- |
| **A. 不写**：界面源码只留在 Session 日志；要留档走文字/18 号对象路径 | 两条渲染面不混，单一事实源；插件保持"不存业务数据" | ✅ **推荐** |
| B. 允许"存为 view" | 需要在对话里跨插件写工作台库；撞 18 号"生成与保存分离"、19 号"不存业务数据"；还要处理 stale | 否（若要，另立项） |
| C. 只存 Session 引用（=A 的另一种说法） | 与 A 等价 | ✅ 等价 A |

**推荐理由**：18 号 `view` 的契约是"模板 + params + dataRefs + basis"，对话界面没有对象引用；硬塞会把两套数据契约揉成一套，并让"哪个是事实源"说不清（17 C4）。用户在对话里觉得有价值的内容，让 Agent 写成文字结论或走 18 号"存为判断/简报"。

### D16 · 是否对模型隐藏 `render_ui` 以外的界面入口

| 选项 | 影响 | 判断 |
| --- | --- | --- |
| **A. 只暴露 `render_ui`**：系统提示只写这一个生成入口；不注册第二个工具名；不让模型直接写 `view` JSON / 直接调工作台工具画界面 | 模型只学一种语言、一条通道；校验单点；不会"二选一"漂移 | ✅ **推荐** |
| B. 再暴露"直接写界面 JSON/HTML"的入口 | 绕过行式语言校验（白名单/上限/URL 全失效）；出现第二套界面语法 | 否 |
| C. 同时暴露工作台 `view.generate` 给对话模型 | 对话里生成页面对象，越过 27 号 G0–G4 的批次与拍板 | 否 |

**推荐理由**：宪章八（不做第二套模型入口 / 无授权写入）+ 17 C4（一个动作一个入口）。模型侧只有一个"界面入口"，插件侧只有一个 key，验收也只有一个面。

### 6.3 canary 规则（借 48 号 §2 的两段法）

1. **干净样本 0 违规**：人工构造"完全合规"的测量数据，门禁必须 0 违规；字段名/量纲写错先在这里红。
2. **注入 1 处必红**：每条门禁注入一处违规，断言 `before 0 → after >0`；没红的门禁视为假绿，按 P0 处理。
3. **跑不起来要明说**：找不到实例/截图目录/插件未加载时，打印"不是通过，是没测到"并 `exit 1`，**不许 skip 当通过**。
4. **canary 自己也要有反例测试**：至少一条"注入后不红"的用例，证明 canary 不是万能的自我确认。

### 6.4 产物与退出码

- 产物：`acceptance/screenshots/<批次>/`（桌面/手机/四态/失败态）、`acceptance/report.json`（每道门禁的 before/after 违规数、canary 结果、版本、sha256、时间）。
- 退出码：任一硬门禁违规 / 任一 canary 没红 / 实例不可用 → `1`；全绿 → `0`。
- 截图与报告脱敏：不含 token、真实地址、会话原文（需要引用时改写为等价示例）。
