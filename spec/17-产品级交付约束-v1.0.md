## 0 · 为什么需要这份约束

46 号审计的结论不是"功能少"，而是"功能做完了，但没有被当成一个产品来收口"：

- 门禁全绿，但字阶可以塌陷、按钮可以有 6 种高度、设置页可以有三种互相矛盾的"定时"说法；
- 真实数据里 11 条建议全部在几秒内被采纳、`basedOn` 0/11，系统从未学到一次"为什么不同意"；
- 飞书四层故障没有一处汇总，用户只能看到"未配置"；
- 手机首屏看不到第一条任务，画布默认 44% 文字 5.7px。

这些不是"再修几个 bug"能解决的，是**从顶层规划到落地执行缺了一条用户可见的验收链**。这份约束把"产品级"从形容词变成可检查的条件。

## 1 · 十条硬约束

### C1 · 依据约束（自上而下）

- 每个改动必须能指回三样：**宪章条款 + 功能编号（F1–F24）+ 本批验收判据**。指不回去的，不做——不是"以后补文档"，是当场不做。
- 每批开工先写"**用户会看到什么、怎么算成、怎么算不成**"，再写代码；禁止"先做再补理由"。
- 信息架构、对象类型、颜色、图标、界面词汇的变更，先登记/讨论，不得顺手加。

### C2 · 用户可见验收（完成定义）

- **完成 = 真实实例 + 真实数据 + 用户会走的入口 + 真实浏览器（1440 / 390）+ 截图 + 三个问题**：找得到吗？不解释能懂吗？能完成吗？
- 以下都不算完成：元素在 DOM 但不可见/在可视区外；记录在非默认页签；主动作跳去了别处；需要用户先读一段解释；需要用户自己猜（例如清空输入框才能重选文件夹）。
- **禁止用内存夹具或造出来的副本替代"用户可见"验收。** 真实数据缺失时写"未验证"，不写"通过"。
- 每个"完成"必须附证据：截图、命令、日志、查询结果；证据要能被下一轮的人复现。

### C3 · 语义门禁（不许假绿）

- 每条约束必须挂一道门禁，或写清一个**具名的人工检查**（谁、看什么、什么算过）。留白等于没人管。
- 门禁必须：有 canary/自检；违反时真的会红；不能写死 `true`、阈值永假、未打开就 skip、空扫描。发现假绿按 **P0** 处理，优先级不低于 UI bug。
- **机械门禁只能证明"在标尺内"，不能证明"层级对/用户能用"**：15px 在字阶内，不代表字阶没塌；组件唯一只登记 2 个签名，不代表按钮只有一套。必须补语义门禁（见 §3）。
- "规范在没有门禁之前，只是一段愿望。"同理：**没有语义判据的"精致"只是文案**。

### C4 · 信息架构（克制）

- 不新增、不删除、不重排一级入口；确需变更先讨论并留痕（宪章第九条）。删入口必须用户点头（2026-10-14 补充约定）。
- **一个视图一个主色主动作**；同一个动作不得有两个入口（顶栏"+ 新建"与页内"+ 新建项目"只能留一个）。
- 筛选/视图默认值不得伪装成用户施加的筛选（"筛选 · 1"必须真的是 1 个筛选）。
- **设置页不是回收站**：首屏只放"授权（文件夹/知识库）+ 能力状态 + 一个与用户目标相关的动作"；版本、设计基线、历史日志收进"关于/折叠"；首屏 ≤1 屏；首屏至少 1 个可点且与用户目标相关。
- **同一事实只能有一个来源**；同一页不得出现两种相反状态（"未接入 / 还没有接入 / 已在运行"不能并存）。
- 新元素必须证明无法被现有元素表达（宪章六·克制）；先删/合并，再新增。

### C5 · 视觉体系（精致）

- **字阶唯一**：11 仅用于时间、坐标等非关键信息；正文 14/22；模块标题 18/26；字重只用 400/550/600；数字一律 `tabular-nums`。**禁止 700**；禁止标题与卡片标题同号。
- **控件唯一**：按钮三档（主/次/文字）；标签一种 pill；输入一种；空态一种；弹窗一种；图标 16/20/24、线宽 1.6；无 emoji；不用文字符号当图标。
- **空数据不得画成数据**：0/0 不画进度环、不画满宽条、不显示假蓝点；空态 = 简笔画 + 一句状态 + 一个下一步按钮。
- **颜色只表达行动/聚焦/真实状态**；不靠颜色单独承担判断；正文对比度 ≥4.5:1、关键边界/焦点环 ≥3:1；深色逐文本节点检查。
- **页头 = 面包屑 + 本页真实提示**；不得全站同一句占位；页面必须有标题，并与 h2/h3 分层。
- **解释性/实现性/设计争论文案禁止进界面**（"最近加载的 50 条""未采用主观健康分""不同维度"）。失败态 = 一句人话 + 一个可点下一步，禁止 JSON/堆栈。

### C6 · 真实数据与证据

- 验收必须写明数据来源、时间、版本；真实库只读副本一律 `/usr/bin/sqlite3 <db> ".backup <dest>"`（WAL 模式，直接 `cp` 会拿到旧快照）。
- 演示/种子/造场景数据必须显式标注，**不得当真实用户行为**；不得用"一次批量点采纳"证明"建议闭环成立"。
- 不得用"11/11 采纳"这种单列分布替代"采纳/改写/否决"的真实分布；没有分布就写"没有分布"。
- 每个交付必须留证：截图、日志、命令、查询；证据与结论一一对应。

### C7 · 助理能力

- **不得在未通过"助理级判据"时，把规则引擎/录入器称为"助理/理解/建议"**。规则能回答"为什么没出声"，不等于"替你想过"。
- **助理级判据（5 条同时成立）**：同一段原始会议材料进来，一次跑通——① ≥3 条判断，依据能点回原始段落/消息/录音秒；② ≥1 处与既有判断或材料内部的矛盾，给双方出处；③ ≥1 条结构化待核对项（问谁/问什么/什么算完成）；④ 3 天后主动提醒一次，写明"为什么现在告诉你"且可点回原判断/原录音；⑤ 改写/否决后理由被记录，下一次建议的 `basedOn` 非空且能点开。
- Agent 通道创建的对象必须带 `origin`（ai/user）；老数据不追溯就如实显示"来源未记录"，不假装。
- `basedOn` 列不出来就自曝"通用建议"；不得编造引用，不得把 `suggested` 写成 `confirmed`。

### C8 · 状态诚实

- 所有能力/定时/通道/集成状态来自**真实探测**；禁止硬编码 `true/false`；禁止同一页两种相反说法。
- 未接入 = 灰字 + 说明 + 下一步；不给假按钮、假进度、假成功；只有真实回执才可说"已保存"。
- **跨插件（IM / 飞书 / Slack / 日历 / Mini）必须有一个健康面**，至少四行：插件加载了吗？渠道连上了吗？会话目录指向工作区了吗？发送代码实现了吗？——缺一行，用户就无法行动。
- **同步与常驻必须有可读状态面**：最后一次成功同步、连续失败次数、失败原因（**哪一侧、哪一跳**）要在同一处可见。**网络不可达不得折成"不算失败"**，也不得只留一句"对端不可达"——它同时掩盖三种完全不同的故障（对面关机 / 本机断网 / 本机定时任务没加载）。依据：2026-10-21 事故（按运行日志核实）——最后一次同步成功是 **10-19 16:30**，之后两天多没有任何运行记录（约 55 小时），10-21 14:14 / 14:15 两次触发都以「对端不可达，跳过这次（不算失败）」收场；而当天深夜实测 SSH 到常驻节点是通的。**定时任务停跑 + 失败被说成正常**，两件事叠在一起，界面没有任何显示，用户与助手都只能靠翻日志猜。
- 定时/心跳/出声的"最后成功时间、连续失败、静默原因"必须来自同一事实源；不得用两套状态各说各话。

### C9 · 审计与数据安全

- **只读审计必须真只读**。任何由审计触发的写入（例如画布缩放按钮"点击即保存"）必须当场停止、还原值，并在报告披露：时间、数量、未还原项。不得删除/隐藏留痕。
- 真实库、凭据、录音、纪要、判断原文、会话记录不得进仓库/发布物/外部服务；发布前先做代码与数据分离。
- 不在输出/日志/报告中泄露 secret/token/个人地址；需要探测凭据时只打印 code/msg。

### C10 · 变更与例外

- 改宪章/VI/本约束走宪章第九条：先讨论 → 记版本与理由 → 旧文归档；不静默漂移。
- 范围变更先讨论；紧急例外需用户明确同意 + 可回滚 + 账本记录，不得成为常态。
- 发现实现与规范冲突，先停下报告：现象 → 证据（文件/行号/截图）→ ≥2 个方案 → 建议 → 影响面。不要只问"怎么办"，也不要自行选边。

### C11 · 代码治理（git）

- **所有代码开发必须走 git**：分支 → 提交 → 合并。**禁止用 rsync / 文件同步搬运代码目录**。
- **唯一来源**：`git@github.com:simmon-clap/dsh-personal-workstation.git` 的 `main`；两台机器都从同一个 commit 出发。
- **每批一个分支**（如 `p0-assistant-backend`）；**合并前必须过门禁与真实用户路径验收**（§2 七关），不允许"先合并再补验"。
- **发包只 build 一次**：同一个产出物装到两端，不各自构建；版本号必须递增，两端版本必须一致。
- **文件同步只同步数据**：`workstation/` 与 `.git` 不进同步范围。
- **判据**：两端 `git rev-parse HEAD` 必须相等；不等时先对齐再继续开发。发布前核对两端版本号。
- **依据（2026-10-21 事故）**：`dsh-sync.sh` 用 `rsync -a --update` 同步整个工作区（含源码与 `.git`），Mini 与笔记本成为**两套仓库**——本机 HEAD `67d895c` 在 Mini 上根本不存在，画布改版差点被覆盖；另因 ssh 未设 `ServerAlive`，一次同步挂死 6 分钟不退。

## 2 · 七关交付流程（按顺序，不许跳关）

| 关 | 名称 | 必须产出 | 不通过的判据 |
|---|---|---|---|
| 0 | **依据关** | 宪章条款 + F 编号 + 验收判据 + 不做什么 | 指不回依据；验收写成"更好用" |
| 1 | **设计关** | 用户路径、首屏、空/失败/加载/无权限四态、视觉层级、文案 | 只有"页面长什么样"，没有"用户怎么完成" |
| 2 | **实现关** | 分层正确（`prototype` 源 / `src` 业务 / `src/v7` 生成物）；Config 白名单；无损 JSON；宿主桩对齐；无硬编码状态 | 生成物手改；加配置键不改 `resolveConfig`；假 ctx 缺宿主服务 |
| 3 | **门禁关** | 机械门禁 + 语义门禁 + canary；红/绿可解释 | 只跑机械门禁就宣布通过；假绿；skip 当通过 |
| 4 | **真实用户路径关** | 桌面 5 条 + 手机 3 条，真实实例/真实数据/真实入口；截图；三个问题 | 夹具通过；元素在 DOM 但不可见；需要解释才能懂 |
| 5 | **证据/账本关** | 做了什么 / 没做什么 / 证据在哪 / 不确定性 / 副作用披露 | 只写"已完成"；不写"没做什么"；证据不可复现 |

**每关的 owner 就是本批 owner；Lead 在关 3/4/5 签字。** 任何一关不过，不进下一关，不发布。

## 3 · 语义门禁清单（最低配置）

机械门禁（现有 `verify`）之外，必须补下列**语义判据**，能机械化的进 `verify`，不能机械化的写成具名人工检查：

1. **页面标题层级**：h1/h2/h3 对应 22/18/15 三档，卡片标题不得比栏目标题粗；无 700。
2. **每页主色按钮 ≤1**；同一动作入口唯一；筛选默认值不算用户筛选。
3. **设置页首屏 ≤1 屏**，首屏至少 1 个可点且与用户目标相关；全页无互相矛盾的同一事实。
4. **空数据不渲染图形**：0/0 不画环/不画满宽条/无假蓝点；空态三件套。
5. **画布默认缩放 ≥60%**，或字号按屏幕像素兜底 ≥12px；<60% 只显示名称+类型。
6. **组件唯一**：按钮/标签/输入/空态/弹窗五种签名各 ≤1 套；图标在册、尺寸 16/20/24、线宽 1.6。
7. **弹窗五条**：居中、Escape、焦点恢复、背景不可操作、未保存保护；危险操作与主操作分离。
8. **移动端**：导航单行（或收进"更多"）；首屏至少 1 条可操作内容；粘性底栏不盖决定字段。
9. **真实用户路径**：桌面 5 条 + 手机 3 条，真实数据，真实入口；不接受夹具。
10. **跨插件健康**：IM/飞书/Slack 的"加载/连接/cwd/发送"四行状态可见，且来源真实。
11. **无假绿**：每个门禁有 canary；`pixel-diff`/`export-browser-check` 这类写死断言的必须修。
12. **文案**：禁造词；解释性/实现性文案 0 处；失败态有下一步。
13. **助理级判据**：C7 五条；不通过不得在界面/文档自称"助理级"。

> 这些判据的第一版落地在 [26-修复与开发方案](26-修复与开发方案-v1.0.md) 的 W0/W1；后续每批新增判据必须先登记到本表。

## 4 · 产品级判据（10 条，全部成立才算产品级）

1. **五条核心路径**可完成：① 新会话/入口 → 记录落库；② 知识 → 判断 → 证据 → 核对；③ 收件箱 → 建议 → 四回应 → 理由；④ 项目 → 阶段/交付；⑤ 手机看 → 判断 → 决定。
2. **设置首屏** ≤1 屏，且首屏有用户目标相关动作。
3. **每页一个主色主动作**，无重复入口。
4. **层级可见**：不看解释能区分页面标题、模块标题、卡片标题、正文、辅助。
5. **空数据不画成数据**；空态有下一步。
6. **画布默认可读**（≥60% 或屏幕像素 ≥12）。
7. **助理级判据** C7 五条通过（同一段原始材料）。
8. **飞书/IM 四层状态**可见、可行动；不出现"未配置"掩盖"未加载"。
9. **不需要读实现说明**：界面上无"最近加载 50 条""未采用健康分""不同维度"这类文案。
10. **真实数据 + 证据**：每条结论都有真实数据、截图、命令；没有就用"未验证"。

## 5 · 禁止清单（在宪章第八条之外新增）

- 把"门禁全绿 / 单测通过 / 元素在 DOM"当完成。
- 把设置页当回收站；把设计文档/实现口径搬进界面。
- 把空数据画成图表/进度环/满宽条。
- 把规则引擎、计数面板、录入器称作"助理/理解/建议"。
- 同一事实两个来源、同一页两种说法。
- 新增入口/颜色/图标/词汇未登记；删入口未获用户同意。
- 700 字重、11px 正文、emoji 图标、文字符号当图标。
- 用演示/种子/造场景数据证明真实闭环。
- 只读审计触发写入不披露。
- 发布物含业务数据/凭据；代码与数据不分离。
- 用"乐观 UI/假成功"替代回执。

## 6 · 责任与记录

- **每批一个 owner**，对七关全链负责；Lead 复核关 3/4/5。
- 每批必须写账本：**做了什么 / 没做什么 / 证据在哪 / 不确定性 / 副作用披露 / 回滚路径**。缺"没做什么"不算完。
- 每批结束做一次"反目标检查"：单测过但界面点不到？记录在非默认页签？主动作跳走？用夹具替代真实数据？门禁假绿？——任一命中，本批 reopen。
- 每 3 批重读宪章九条标题 + 本约束十条，确认没有自发概念/入口/颜色/词汇。
