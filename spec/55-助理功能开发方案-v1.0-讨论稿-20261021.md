## 0 · 这次要解决什么（用户会看到什么）

| 现在 | 之后 |
|---|---|
| 你发一条消息，它可能没下文 | 每条输入都有归属，最差也会有人说「记下了 / 这事不用你管 / 需要你一句话」 |
| 东西悬着，你不知道谁在等谁 | 每个事项都有终态；悬着的必须写明「在等谁、等到什么时候」 |
| 定时任务停了没人知道 | 常驻节点每 15 分钟记一笔；停超 45 分钟就告警 |
| 提醒要么不来，要么一次来一堆 | 早晚两个开口点，每条都能回答「变了什么 / 意味着什么 / 能做什么」 |

**怎么算成**：五个入口真实走过一遍，每条输入都能查到最后去了哪；人为弄停常驻节点，45 分钟内能看到告警；每条出声都能答三问。
**怎么算不成**：只在单测里过、界面上看不到、或靠造数据演示（17 C2 禁止）。

## 2 · 结构：一趟的路径

```
① 入口（9 个）
   页面 / 对话 / 飞书 / 语音 → 收件本
   日历 / 邮件 / 资料 / 健康 → 只读，进着落本
   定时（每 15 分钟）→ 心跳本
        │
        ▼
② 后台（一次醒来的六步）
   接住 → 归属 → 三问 → 决定（说/攒/不说，不说写理由）→ 办 → 记着落
        │
        ▼
③ 出口（只有三个 + 一处状态区）
   零级 只存档 · 一级 收件箱排前面 · 二级 飞书一条消息 · 状态区 常驻可见不打扰
```

**出口的硬规则**：二级（能打断你）必须同时满足「与承诺直接相关 + 有新事实 + 同类没说过」；不满足就降级，并写明降级原因。

## 3 · 数据契约

三张新表，全部是**运行记录**（与 `heartbeat_runs`、`speak_feedback` 同类），不是业务对象：不进画布、不进收件箱对象列表、不参与实体版本与批次治理。

```sql
-- 收件本：每条输入都落一行
CREATE TABLE intake(
  workspace TEXT NOT NULL, id TEXT NOT NULL,
  at TEXT NOT NULL,                    -- 收到时间
  source TEXT NOT NULL,                -- page|chat|im|voice|calendar|mail|file|health|timer
  source_ref TEXT,                     -- 原对象/消息 id（不存正文）
  summary TEXT NOT NULL,               -- 一句话，≤200 字
  state TEXT NOT NULL,                 -- captured | not_mine | needs_you
  reason TEXT,                         -- state≠captured 时必填
  subject_kind TEXT, subject_id TEXT,  -- 归到哪个对象
  unassigned INTEGER NOT NULL DEFAULT 0,
  run_id TEXT,                         -- 哪次判定接住的
  PRIMARY KEY(workspace,id)
);

-- 着落本：每个事项最后去哪了
CREATE TABLE loop(
  workspace TEXT NOT NULL, id TEXT NOT NULL,
  subject_kind TEXT NOT NULL, subject_id TEXT NOT NULL,
  state TEXT NOT NULL,                 -- done | dropped | handed_off | waiting
  waiting_for TEXT, waiting_until TEXT,-- state=waiting 时必填
  opened_at TEXT NOT NULL, closed_at TEXT,
  note TEXT,
  PRIMARY KEY(workspace,id)
);

-- 心跳本：常驻节点的存证
CREATE TABLE beat(
  workspace TEXT NOT NULL, seq INTEGER NOT NULL,
  side TEXT NOT NULL,                  -- resident | laptop | phone
  at TEXT NOT NULL, source TEXT NOT NULL, -- timer | manual
  PRIMARY KEY(workspace,side,seq)
);
```

**约束（写进校验，不靠自觉）**

1. `intake.state` 只能是三个值；`not_mine` / `needs_you` 必须带 `reason`。
2. 归不上就 `unassigned=1`，**不猜**（F3）。
3. `loop.state='waiting'` 必须同时有 `waiting_for` 与 `waiting_until`，否则拒绝写入——**"在等"没有条件就会变成永久悬案**。
4. 三张表都进同步范围（宪章 v1.4 第七条：数据对等）。
5. 判活只读 `beat`，**不读 ssh、不读日志**。

**库会变大吗**：日增约 50–250 行、几十 KB；十年 100–300 MB。对比 `voice/` 目录 251 MB，不是体积问题。

## 5 · 分批（顺序即依赖，不得并行）

### P0 · 前置：让状态可读（0 token）

- 产出：`beat` 表 + 常驻节点每 15 分钟写入 + 同步 job 修复（`launchctl bootstrap`、超时 8s→30s、加一次重试）+ 状态面三行
- 验收：人为 `launchctl bootout` → 45 分钟内状态面变红；恢复后自动回绿；`verify:liveness` 由红转绿
- 风险：改的是系统级 job，**先备份 plist，再动**

### P1 · 接住（不漏）

- 产出：`intake` 表 + 页面入口 → 对话 → 飞书 → 语音（逐个）
- 验收：五个入口真实各走一遍，`intake` 有对应行；一条输入必须落到三选一状态
- 不做：日历/邮件的写入（它们只进着落本）

### P2 · 着落（不悬）

- 产出：`loop` 表 + 心跳加"超期无终态"规则 + 悬空项列表（复用现有收件箱视图，**不加新页面**）
- 验收：能列出所有悬空项与"在等谁"；`waiting` 缺条件的写入被拒
- 门禁：新增单测覆盖"四档终态 + waiting 必填"

### P3 · 判断（够深）

- 产出：候选 → 三问过滤 → 两个开口点（09:30 / 21:00）+ 不说的理由进留痕
- 验收：每条出声能答三问；被过滤的写明缺哪一问
- 成本：仅候选上跑，每天 ≤ 6 次生成，≤ 3 万 token/天

### P4 · 出口与收口

- 产出：收件箱分组 + 状态区 + `verify:liveness` 接入 `npm run verify`
- 验收：桌面 1440 + 手机 390 各截图；三个问题（找得到 / 不解释能懂 / 能完成）全"是"

## 11 · IM 二级出声的能力现状（2026-10-22 核实，P4-b）

D1 定的是「覆盖全部 IM 助理频道」，所以这一条不是"只做飞书"，而是**能不能从工作台插件主动发一条消息**。

**核实结论：当前宿主没有对插件暴露「主动发消息」的能力，二级出声做不了。**

| 查了什么 | 结果 |
|---|---|
| `@michengai/dsh-im-connect`（0.1.68，本机已装） | 只在**收到消息后回复**时发送（gateway 内部 `channel.beginReply`）；**没有注册可被其他插件调用的发送服务**（`lib/index.js` 里没有 `ctx.set/provide` 暴露通道） |
| `@deepseek-ai/dsh-schedule` | 宿主包里，未解包，**其「创建」能力与"投递到哪个会话"未核实**；本机只验证过 `list()` |
| 工作台现有 `imHealth` | 只读四层健康（加载/连接/目录/发送代码），**不能发** |

**所以现在的行为**（不伪造）：

- 二级（能打断你的那一级）**不可用**，`speak.mjs` 如实降级为一级（收件箱排前面），并把降级原因写进结论；
- 开口记录照常写进 `opening`，你下次打开工作台就能看到——**它没有丢，只是不主动推**。

**补丁已经备好了（2026-10-22，未应用、未安装）**：`~/Desktop/DSH/im-connect-slack/0001-feat-POST-channels-id-send.patch`
—— 在本地 fork 上新增 `ImEngine.sendProactive(channelId, chatId, text)` 与
`POST /dsh-im-connect/api/channels/:id/send {chatId, text}`（400 缺参数 / 502 发送失败带原因），
`tsc` 编译通过。应用方式：`git am` 到 fork → `sh rebuild-and-install.sh` → 完全退出并重开 DSH。

**要真正打通二级，只有两条路，都需要在宿主侧动手（不在本插件范围内）**：

1. 在 IM 插件里暴露一个发送服务（如 `ctx.provide('imSend', {send(chatId, text)})`），工作台通过 `ctx.get('imSend')` 调用；
2. 或核实 `schedule` 的创建能力能否**投递到指定会话**；能的话由它代发。

**门禁口径**：界面与留痕里不得出现"已推送"；降级必须写明原因（17 C8）。
