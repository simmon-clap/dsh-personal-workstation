# 个人工作台 · 现状评估与改造清单 v1.0

评估对象：`dsh-personal-workstation`（评估时点 2026-10-13，包版本已从 1.10.0 推进到 **1.11.0**）
评估依据：[01-顶层宪章](01-顶层宪章-v1.0.md) · [02-VI 规范](02-VI规范-v1.0.md) · [03-功能与交互设计](03-功能与交互设计-v1.0.md) · [04-开发规划与约束](04-开发规划与约束-v1.0.md)

## 0 · 一句话结论

> **1.10.0 是一个基础扎实的"事务型台账"，不需要重做；它缺的正好是宪章里最重要的两块（判断、建议闭环），另有一批可机械清理的 VI 债务。**

四项关键数字：

| 指标 | 实测 | 含义 |
|---|---|---|
| 已有对象类型 | 12 种，与登记表**完全一致** | 对象模型不用动 |
| 一级视图 | 7 个 + 设置，与登记表**完全一致** | 信息架构不用动 |
| 判断 / 建议对象 | **0 个文件命中** | 宪章第三、四条**零实现** |
| 字面色值 | **384 处**（宪章守卫口径，见 批次 0 账本） | 违反门禁 1，需收敛 |
| `!important` | **32 处**（`v7-contrast.css` 13 · `v7-visual.css` 12 · `v7-shell.html` 5 · `web-app.mjs` 3） | 违反 V6，比自己以为的多 |
| 消费宿主主题变量 | `--dsw-*` **0 处** | V6 完全未做 |

**一个必须说清楚的事实**：上一轮审计记的是"`!important` 3 处"，本轮机械扫描是 **32 处**。这类债务会自己长 —— 这正是批次 0 要先建门禁的理由。

> **口径说明**：本表数字已统一为**宪章守卫**（`prototype/charter-guard.mjs`，批次 0 交付）的输出，它是唯一权威口径：字面色值 384 · `!important` 32 · 间距标尺外 322 · 字阶外 50，合计 **788 处存量债务**。守卫的棘轮基线在 `spec/guard-baseline.json`，**任何一项上升即门禁失败**。

### 新-4 的一个必须先拍板的问题（否则批次 3 无法开工）

**"建议"要不要成为新的对象类型？** 两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（我建议）** | **不新增对象类型**，复用现有"收件箱里的待决定项"，给它补四个字段：依据、不确定性、你的回应、你的理由 | 数据模型不变，符合"克制"；但需扩展现有批次条目的 schema |
| B | 新增独立 `advice` 对象 | 模型更干净；但新增对象类型属于范围变更，且会与收件箱产生两套"待决定"入口 |

**我建议 A**：宪章第六条"克制"要求新元素必须证明无法被现有元素表达 —— 建议本质就是"待你决定的条目"，收件箱已经有这个概念了。**这一条需要你点头，因为它动数据模型。**

## 7 · 不可回避的代价（先说清楚）

1. **批次 5 会让推进变慢**：VI 收敛是纯成本，不产生新功能。但做完之后每个新功能都省事 —— 这是精致明码标价的代价。
2. **判断（批次 1–2）要先于建议（批次 3–4）**：没有判断可参考，建议就是无依据的猜测，"为什么这么建议"会永远列不出来。
3. **心跳排在最后不是保守**：给一个还没有判断能力的系统装主动打扰，等于让它用"事务"来打扰你 —— 那正是宪章第六条要防的。
4. **1.10.0 的 19 处 `!important` 提示一件事**：没有门禁的债务会自己长。所以批次 0 不是可选项。
