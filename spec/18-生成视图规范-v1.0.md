> **依据**：宪章 v1.4 第三 / 四 / 五 / 六 / 七 / 八条 · 02-VI 规范 · 03-功能与交互设计 · 17-产品级交付约束 C1–C10 · 13-技术与架构规范 §4（能力可选接入）
> **状态**：**v1.0 冻结（2026-10-18 用户拍板：直接开始做、全部搞定）**。决策门 D6–D11 已按推荐项拍板（见 [27-生成视图开发方案 v1.0](27-生成视图开发方案-v1.0.md) §2）。
> **日期**：2026-10-18
> **一句话**：生成视图 = **由 Agent 依据真实对象生成、由工作台渲染、可保存可复现的视图**；不是一个新页面，也不是一段自由 HTML。

---

## 0 · 为什么需要它

固定界面的价值是**稳定、可比、可审计**；代价是**答不了"这次的问题"**。工作台里已经出现三类具体卡点：

| 卡点 | 证据（现状） |
| --- | --- |
| 项目类型异构，详情却是同一套面板 | `prototype/project-detail.mjs` 注释原话："面板对所有项目都用同一套结构"；尽调、研发、合作、研究看到的是同一批区块 |
| 知识是探索性的，卡片流只适合看单条 | 知识页是判断 / 材料 / 专题的卡片流（`prototype/knowledge-view.mjs`），没有"多份材料对比"的呈现 |
| 任务卡住的解释散落在字段里 | 任务详情里"等待原因"只是一个可编辑字段（`prototype/task-detail.mjs`），没有"卡在哪、等谁、下一步"的整体解释 |

**但不要因此生成一切。** 收件箱、项目/任务列表、设置页恰恰需要**每次长得一样**：收件箱要比较同类建议、要统计采纳率、要回看理由（宪章第三 / 四条）；列表要扫描；设置要稳定。**生成视图只出现在"问题形状会变"的地方。**

---

## 1 · 定义与三个特征

一条生成视图必须同时满足：

1. **数据有引用**：展示的每个值都能映射到真实对象的字段（`dataRefs: id@revision`），模型不得产生新事实；
2. **生成有依据**：至少 1 条 `basis`，可点回原对象；
3. **结果可保存**：用户认为有价值 → 保存为 `view` 对象（或转存为判断 / 简报），下次打开还在；不保存就是一次性预览，关闭即弃并明说。

**它不是**：
- 自由 HTML / iframe / 任意脚本（安全与规范双重不可控）；
- 聊天记录的嵌入式网页；
- 新的页面或一级入口；
- "AI 画的图"当证据。

## 2 · 边界（v1 白名单与不做清单）

### 2.1 做什么（v1 只允许这四类模板）

| 模板 id | 用在哪 | 回答什么问题 | 呈现 |
| --- | --- | --- | --- |
| `risk-matrix` | 项目详情 | 这个项目现在最大的风险是什么？证据够不够？ | 风险 × 证据强度矩阵 + 每条出处 |
| `timeline` | 项目详情 | 里程碑 / 交付 / 判断的时间顺序，哪一步在等 | 横向时间轴 |
| `compare-table` | 知识页 | 这几份材料/判断在关键维度上说法一致吗？ | 维度 × 来源 对比表 + 分歧标记 |
| `blocker` | 任务详情 | 卡在哪、等谁、下一步做什么 | 阻塞链 + ≤3 个可点动作 |

### 2.2 不做什么

- 不生成收藏 / 列表 / 收件箱 / 设置页的布局；
- 不做整页生成、不做"第二套界面"；
- 不运行自由 HTML / iframe / 脚本；
- 不把模型输出直接写进业务字段；
- 不把视图当证据（要留档走"存为判断/简报"）；
- 不生成收件箱里的"建议卡"（四回应结构必须固定）；
- 不新增一级入口、不新增页面、不新增界面词汇（除非先登记 registry）。

## 3 · 契约（view v1）

### 3.1 对象

```json
{
  "kind": "view",
  "title": "示例项目 · 风险与证据",
  "template": "risk-matrix",
  "subject": {"id": "pr-1", "kind": "project", "revision": 7},
  "params": {"horizonDays": 90},
  "dataRefs": ["pr-1@7", "j-3@2", "e-9@1"],
  "basis": [{"kind": "file", "ref": "会议纪要.md@3", "quote": "…"}],
  "generatedAt": "2026-10-18T13:40:00+08:00",
  "origin": "ai",
  "state": "fresh",
  "actions": ["open-subject", "save-as-judgment"]
}
```

### 3.2 字段规则

| 字段 | 规则 |
| --- | --- |
| `template` | **白名单**，未登记模板直接拒绝渲染（不降级、不猜） |
| `subject` / `dataRefs` | 必须是真实、未归档对象；`id@revision` 格式；上限 50 条 |
| `params` | 每个模板有自己的 schema（枚举 / 长度 / 上限），服务端校验 |
| `basis` | ≥1 条；沿用判断的 `evidence` 词表（message / file / audio / web / note） |
| `origin` | `ai` / `user`；老数据缺省显示"来源未记录"，不假装 |
| `state` | `fresh` / `stale`；引用对象 revision 变化 → `stale`，界面显示"依据已变，需复核" |
| `actions` | v1 只允许 `open-subject` / `save-as-judgment` / `save-as-brief`；其他动作先登记 |
| `savedAs` | 转存后的对象 id（可选） |
| `analysis` | **v1.1 新增**：AI 解读。`{summary?≤600字, findings?1–8条[{ref,text≤300}], uncertainty?≤300字}`；每条 `ref` 必须在 `dataRefs` 内，`origin` 必须是 `ai`；无依据/编造引用直接拒绝。这是模型唯一可写的位置，模板数据仍由服务端从真实对象生成 |

### 3.3 生成与保存分离

- **生成**（`view.generate`）：只返回预览，**不落库**；
- **保存**（`view.save`）：走现有 `draft → 收件箱确认 → 回执可撤销`，不直接写库；
- 生成失败/取消 → 不产生对象、不留半成品。

## 4 · 渲染规则（VI 收口）

| 项 | 规则 |
| --- | --- |
| 容器 | 详情弹窗内区块（项目 / 任务）或独立居中弹窗（知识对比）；**不新增页面** |
| 组件 | 只用 registry 已登记组件：卡片 / 表格 / 标签 pill / 按钮三档 / 空态三件套 |
| 字阶 | 按 02：正文 14/22、模块 18/26、辅助 12/18；禁止 700 |
| 颜色 | 只用 `--ws-*` token；不新增颜色，不靠颜色单独承担判断 |
| 图标 | 在册图标，16/20/24、线宽 1.6 |
| 出处条 | 每个视图顶部一行：`AI 生成 · 依据 N 条 · 数据截至 YYYY-MM-DD HH:MM`，依据可点 |
| 四态 | 空：缺哪些数据 + 一个下一步（去补材料 / 去建判断）；加载：骨架，不留空白；失败：一句人话 + 重试 + 看原始列表；无权限：如实说明 |
| 移动端 390 | 表格可横滚或折叠成卡；对比度 ≥4.5:1；焦点环 3px；键盘可达 |
| 动效 | 生成中只做骨架，不做打字机 / 闪烁 / 装饰动效（宪章八：装饰性动效不做） |

## 5 · 数据、出处与失效

1. **只读真实对象**：通过受控接口读取，不直连数据库、不读其他插件内部数据（13 号技术规范：插件只通过已核验 Service / 受控适配接口集成）。
2. **字段映射**：每个展示值必须能落到 `dataRefs` 里的字段；落不到的（推断、估计）**不显示数字**，只能以文字出现在"不确定"里。
3. **不替代判断**：视图是阅读面；用户认可的内容 → "存为判断"（带依据 / 不确定性 / 什么时候成立）或"存为简报"，进入宪章第三 / 四条的闭环。
4. **失效**：`dataRefs` 的 revision 变化 → `stale` + "依据已变，需复核"（与 `relationStale` 同一套口径，不另造状态）。重新生成是显式动作，不静默刷新。

---

## 6 · 复现、保存与导出

- 保存的是**定义**（模板 + 参数 + 引用 + 生成时间），不是渲染快照；重新打开按当前数据重算。
- 需要留档时**另生成文档**（带出处与生成时间），走 02 §10 分享规则；视图本身不承担"证据"角色。
- 视图**不进画布、不参与关系派生、不影响图谱**（`graph.mjs` 排除 `view`）。

## 8 · 验收判据（语义门禁，最低配置）

| # | 判据 | 怎么查 |
| --- | --- | --- |
| G1 | **出处率 100%**：每条视图 ≥1 条 basis 且可点回 | 单测 + 浏览器点开每条依据 |
| G2 | **字段映射 100%**：无模型自造字段/数字 | 渲染前校验 `dataRefs`，造一条越界数据应拒绝 |
| G3 | **四态齐全**：空 / 加载 / 失败 / 无权限各一句人话 + 下一步 | 浏览器注入四态截图 |
| G4 | **动作全部走草稿**：无直接写库 | 抓写路径 + 回执可撤销 |
| G5 | **可复现**：同一 view 重开，模板/参数/引用一致；改数据后显示 stale | 单测 + 真数据 |
| G6 | **视觉合规**：只用登记组件/字阶/颜色/图标 | 现有 style/craft/type 门禁扩一条"生成视图容器" |
| G7 | **不新增入口**：一级入口与页面集合不变 | registry + charter-guard |
| G8 | **双端无溢出**：1440 / 390 无横向溢出，对比度 0 违规 | 现有 mobile / contrast 门禁 |

**每条门禁必须带 canary**：故意注入"无依据视图 / 越界字段 / 直接写库"各一条，门禁必须变红；否则视为假绿（17 C3）。
