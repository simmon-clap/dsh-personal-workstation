## 2 · 七处不一致（A–G，按严重度排序）

### A · 运行实例 ≠ 仓库 ≠ 已装包（宪章六 诚实）

**实测（可复现）**：从运行中的 DSH 取会话 cookie，直接下载浏览器真正加载的模块：

```
GET /personal-workstation/v7/space-view.mjs          → 200, 62997 字节
sha256 = b6f141090c2ddedf4cf6e64e7e3af687f11984a59c440e8c9d9f214bb3906243
逐包比对 releases/*.tgz → MATCH: dsh-personal-workstation-2.3.0-b20261015173534.tgz   （10-15 17:35）
```

而同一时刻：

| 对象 | 事实 |
|---|---|
| 已装包（profile 依赖） | `releases/dsh-personal-workstation-2.4.0-b20261016035858.tgz`（今天 11:58:58） |
| 工作区源码版本 | 2.4.0 |
| DSH 进程启动 | 今天 09:20:01 |
| **浏览器实际加载** | **10-15 17:35 那一份** |

**用户看到的设置页逐行（实测）**：

```
[version] 版本说明 = 2.3.0 界面资源 2026-10-15 17:35 · 与正在运行的一致
[base]    数据根目录 = 微信工作区 /Users/simon/Desktop/DSH/微信工作区
[cap]     读文件 = 已接上 可读 1 个文件夹、可写 1 个文件夹：test
```

而 profile 配置里写的是：

```yaml
rootDirectory: /Users/simon/Desktop/DSH/飞书工作区
fileGrants: [ {id: root-workspace, label: 工作台根目录（读写）}, {id: voice-inbox, label: 语音目录（只读）} ]
```

**即：根目录、授权目录、界面资源，三样全都是旧的。**

**根因是代码级的，不是"忘了重启"这么简单**：

```js
// src/runtime-status.mjs:7,25
const builtAt = statSync(<已加载模块所在包的 src/v7-shell.html>).mtime;
const processStartedAt = Date.now() - process.uptime()*1000;
const needsRestart = builtAt > processStartedAt;      // ← 恒为 false
```

插件是**进程启动时加载**的，所以"已加载模块的文件时间"**永远早于进程启动时间** → `needsRestart` 结构上不可能为 true。它只能发现"文件在进程启动后被改"（开发态热更），**发现不了 `spec/10 §四` 想防的那件事：装了新的、没重启**。

而且它给出的那句话是**反向安慰**：「与正在运行的一致」——字面为真，但用户真正需要知道的是「**你正在看的不是已装的那一份**」。

> 这一条与用户长期反馈的模式严丝合缝（"你说的没实现/找不到"）：**不是我做的没生效，是整个验收对象都不是用户在看的那个**。

`spec/coverage.json` 的 75 条 = 四份规范的全部 h2/h3 标题（宪章 12 · VI 16 · 功能 20 · 约束 27），**无缺漏无多余**。但：

#### G.3 时序（源 vs 产物）与"两条没有的门禁"

- **27 道门禁里 26 道检的是产物**（`src/**`）；真源在 `prototype/*.mjs` + 仓库根的冻结原型 + `design-system/`。
- `npm run verify` 第 1 步会 `build-v7` 重建产物 → 链内不会"源改了没 build"；但**单独跑的 20+ 个 npm 脚本都不 build**（`verify:craft`/`verify:ux`/`verify:coverage`/`verify:style`/`verify:controls`/`verify:judgment`…）→ 源改了没 build 时它们检旧产物 = 假绿。
- `build-v7` **不清理** `src/v7`（无 `rmSync`）→ 删掉的模块会留成孤儿产物。
- `spec/10 §四` 说的两条"当前没有门禁"**核实为真**：① 客户端资源与服务端代码版本一致 —— 无门禁；② "重启后才算生效" —— `needsRestart` 只出现在渲染里，**`test/` 与 `prototype/` 里没有任何断言**。而 `client/client.js`（随包发布）**不在 charter-guard（只扫 src）、不在 wording-audit（只扫顶层 .mjs）、不在 css-var-audit 的范围内**。

#### G.5 方法论结论（最重要）

所有浏览器检查脚本一律在**内存库 + 自播种数据**上跑（`:memory:` + `seedVisualStore` + 脚本内手写 seed）。
**所以"全绿"只能证明"界面机器可跑"，不能证明"这件事在真实数据里发生过"。** 本报告第 2.B 节的判断/建议闭环就是最好的例子：34 项 + 18 项全 PASS，真实数据 0 条。
