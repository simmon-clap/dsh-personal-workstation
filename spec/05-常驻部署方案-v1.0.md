## 0 · 这份文件要解决什么

工作台现在跑在笔记本上，**笔记本合盖就停**。而工作台的核心能力里有一半要求长期在线：

- 每天 9:30 / 21:00 生成信息简报，推到微信
- 你从微信回一句话，助理在**同一个会话**里接着处理
- 出差时用笔记本或手机看任务、看文件、继续干活

所以需要一个**常驻节点**：一台长期开机、放着事实源、能独立执行任务的机器。宪章第七条已经为这个角色留了位置（"实现就是你家那台 Mac mini"），这份文件把它落到可执行的步骤。

## 1 · 宪章逐条检查

按《顶层宪章》九条逐条对照。**推导不出来就不做**（第九条）。

| 条款 | 原文要点 | 本方案如何满足 | 判定 |
| --- | --- | --- | --- |
| 第一条 终极愿景 | 工作围绕你展开 | 你在任何设备上都看到同一份工作状态 | ✅ |
| 第二条 三重身份 | 助理 / 判断 / 记录 | 常驻让"助理"这部分真正成立（能在你不在时做事） | ✅ |

| 第六条 品味 | 诚实 / 安静 / 克制 / 有重量 / 耐用 / 精致 | 一天两条简报、没内容不生成；未接入就写未接入 | ✅ |

| 第七条 可读 | 不依赖隐藏手势、所有状态都有文字 | 部署后设置页照常如实显示"接上了什么" | ✅ |
| **第八条 边界** | 明确不做：**无授权读写** · 用模型置信度替代授权 · 无回执的假成功 | **这是本方案最关键的一条**：Finder 挂载那条通道**必须只读**，理由见第 4 节 | ✅ |
| 第九条 修改规则 | 现实证据可以推翻条文，但要走讨论流程 | 本方案不修改宪章，只兑现第七条已经写下的"常驻节点" | ✅ |

**品味六条自查**：

- **诚实** —— 本方案明确区分"工作台授权目录"与"macOS 文件共享"两套边界，不声称挂载之后的一切读取都受工作台管（你的研究文档里也写过同一条："不声称电脑上的一切读取都能仅限一个目录同时保持任意软件正常运行"）。
- **安静** —— 部署本身不产出任何界面噪音；设置页只多一行"数据根目录"（已实现）。
- **克制** —— 只引入**一个**第三方软件（Tailscale），其余用 macOS 自带。不因为"能装"就多装。
- **有重量** —— 迁移完成后跑 `npm run accept` 验收，不是"搬过去看着像好了"。
- **耐用** —— 不引入需要长期维护的自建服务（不写 cron、不写守护进程、不用同步盘）。
- **精致** —— 不涉及界面。

## 2 · 架构

```
                        ┌──────────── 你在哪 ────────────┐
   在家 / 同一 Wi-Fi     │                               │   在外
   笔记本浏览器 ─────────┤                               ├── 手机 / 笔记本浏览器
   Finder（SMB，只读）───┤                               │      （经 Tailscale）
                        └───────────────┬───────────────┘
                                        ↓
                        ┌─────────  Mac mini（常驻节点）─────────┐
                        │  DSH App · desktop profile              │
                        │   ├ 个人工作台插件                      │
                        │   ├ IM Connect（微信）                  │
                        │   ├ dsh-schedule（09:30 / 21:00 定时）  │
                        │   ├ 根目录：业务文件（唯一真源）        │
                        │   └ workstation-data/（SQLite，唯一真源）│
                        └────────────────┬───────────────────────┘
                                         ↓
                              微信：简报推给你 · 你回一句
```

**一句话**：**只有一份数据，就在 mini 上**。笔记本和手机是客户端，不是副本。

### 多端同步：本文件不做，另有专门设计

**2026-10-15 宪章第七条修订为 v1.1**：常驻节点仍是事实源所在，但**允许客户端离线持有副本**，恢复连接后按对象级合并。

所以本文件**不再主张"只做单一 Host"**。分工是：

| 文件 | 负责 |
| --- | --- |
| **本文件（05）** | 把常驻节点立起来：装什么、怎么迁、边界怎么划 |
| **`06-双端同步设计`** | 两台机器之间怎么保持一致（对象级合并 + 文件同步 + 冲突留痕） |

**但仍有一条不变**：数据的事实源在常驻节点。同步是为了让客户端能离线干活，不是为了取消事实源。

## 3 · 要装什么

| 装在哪 | 什么 | 为什么 | 来源 |
| --- | --- | --- | --- |
| mini | **Tailscale** | 组网。在外也能连回家，免公网 IP、免端口映射 | **第三方（唯一一个）** |
| mini | 「文件共享」(SMB) | Finder 挂载访问业务目录 | macOS 自带 |
| mini | 「屏幕共享」 | mini 无显示器时，首次登录桌面会话（Electron 版 DSH 需要） | macOS 自带 |
| mini | DSH App + `desktop` profile + 工作台插件 + IM Connect | 与笔记本**同版本** | 现有 |
| mini | `@deepseek-ai/dsh-experimental-schedule-bundle` | 宿主级定时，**不自己写 cron** | DSH 自带（当前未装） |
| 笔记本 | **Tailscale** | 同一账号登录即通 | **第三方** |
| 笔记本 | 无 | Finder 原生支持 SMB | — |

**结论：只装 1 个第三方软件。** 其余全是 macOS 或 DSH 自带。

## 4 · 两条通道的边界（本方案最关键的一节）

工作台的授权模型是「读写受**授权目录**约束」（数据与交互契约①）。而 Finder 挂载是**操作系统级**的，它**绕过**工作台那道闸门。

**不假装它们是一回事，而是把两条边界分开写清楚：**

| 通道 | 边界由谁决定 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| **工作台** | `rootDirectory` + `fileGrants` | 读写、编辑、存回、内嵌预览 | 越出授权目录 |
| **Finder 挂载** | macOS 文件共享权限 | **只看、只取** | 改文件（**只读**） |

### 三条写入路径（这一节纠正了 v1.0 初稿的一处混淆）

初稿把"Finder 只读"说成会影响助理产出文件——**这是错的**。实际有三条互不相同的写入路径：

| 谁在写 | 走哪条路 | 权限 | 有记录 / 可撤销 |
| --- | --- | --- | --- |
| 你在工作台界面里改 | 工作台受权通道（`fileGrants`） | 读 + 写 | ✅ 有回执、可撤销 |
| **助理产出报告 / 分析 / 交付物** | **同一条工作台受权通道** | **读 + 写** | ✅ 落进项目文件夹、进工作台记录 |
| 你在 Finder 里手动改 | SMB 挂载 | **只读** | ❌ 没有 |

**所以"让它做分析、把报告放进对应项目的文件夹"完全没问题** —— 那是第二条路，走工作台自己的授权（根目录已授权读写），与 SMB 只读无关。工作台本来就支持写文件到授权目录内。

只读限制的只有第三条：**人拿 Finder 当文件管理器手动改**。

### 为什么 Finder 那条必须只读

宪章第八条把「**无授权读写**」列在"明确不做"里。

写权限的挂载会让文件改动**绕过工作台的记录**：改了就是改了，没有回执、没有"已保存 · 撤销"、也没进判断与依据链。那正是"无授权读写"加"无回执的成功"两种情况叠在一起 —— 两条都踩。

所以：**SMB 只读**。要在 Finder 里改文件这件事，**不做**；改文件走工作台。

（若以后确有刚需，那是一次**契约修订**，要按第九条先讨论，不能顺手放开。）

### 三条硬约束

1. **SMB 只共享业务目录**（`/Users/<mini>/DSH`），**不共享整个家目录**
2. **Tailscale 只对你账号下的设备开放**，不对公网开放 —— 不把 mini 暴露到互联网
3. **用一个独立的共享账号**（不是主账号），权限限定在上面那个目录

## 5 · 迁移步骤

**前置**：三项参数已确认（见第 7 节）。

1. mini 装**同版本** DSH，建同名 `desktop` profile，装工作台插件 + IM Connect
2. 笔记本**停** DSH → 用 `rsync` 把两个目录搬到 mini：
   - `workstation-data/`（SQLite 与授权表，**必须停进程再拷**）
   - 根目录（业务文件）
3. 改 mini 上的 `rootDirectory` 与 `dataDirectory` 为新路径
4. mini 上微信**重新扫码**一次；改飞书通道的 `cwd`（现在写死的是笔记本路径）
5. 开启 SMB（只读、限定业务目录）+ Tailscale + 屏幕共享
6. 跑 `npm run accept` 验收 —— 本地全量门禁 + 真入口复验，**绿了才算搬完**

> 第 6 步是这个仓库既有纪律的延续：不接受"看着像好了"，要有退出码。

## 6 · 风险与明确不做

**风险**

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 微信换设备要重扫 | 会断一下 | 提前知会；重扫即可 |
| 飞书通道 `cwd` 写死笔记本路径 | mini 上路由失败 | 迁移第 4 步一并改 |
| mini 无显示器时 Electron 会话起不来 | DSH 起不来 | 先经「屏幕共享」登录一次桌面会话 |
| 家里断网 / 停电 | 简报停发 | 恢复后补发一条，并在简报里说明中断（不假装没发生） |

**明确不做**

- ❌ 本文件不做多端同步（那是 `06-双端同步设计` 的范围；这里只立节点）
- ❌ 不给 SMB 写权限（宪章第八条"无授权读写"）
- ❌ 不把 DSH 端口暴露到公网
- ❌ 不自己写 cron / 守护进程（用 `dsh-schedule`）
- ❌ 不用 iCloud / 同步盘放工作台数据（SQLite 会坏）
- ❌ 不在笔记本上再跑一个工作台（那就是第二个事实源）
