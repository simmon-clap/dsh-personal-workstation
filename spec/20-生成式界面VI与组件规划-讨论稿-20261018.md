### 0.1 看完 demo 的结论（诚实版）

**已经成立的**
- 21 个组件全部能渲染；真实 OSM 瓦片地图可用，路线/标记能画；时间线、表格、统计、表单、按钮、建议都能点。
- 390px 无横向溢出（4 张卡实测：`docWidth=390`、卡片 350）；暗色主题自动跟随（只换 token，组件零改动）。
- 卡片里所有事实都来自真实内容或明确标注的示例；没有编造数字。

**明显还不好（确认 VI 方向后修）**
1. **图表**：柱体是纯黑（宿主 `brand-primary`），每个刻度都带单位导致拥挤、X 轴标签截断；缺数据色板与标签策略。
2. **层级**：整张卡黑白灰，卡片/表格/时间线之间的视觉层级主要靠 1px 边框，远看"平"。
3. **地图**：标记文字与地图自带地名互相压；路线偏细；暗色下瓦片仍然高亮，需要降噪（暗色滤镜/遮罩）。
4. **Tab**：选中态只有一条很淡的下划线，看不出当前页签。
5. **Gallery**：外链图片偶发加载失败时占位文案停在"图片加载中…"，应超时后给失败说明。

**本轮已修**
- Badge / Chips / Buttons 在 Row 里被拉满整行的缺陷（改为内容宽度）——对比上一版截图可见。

## 1 · VI 顶层规划：三层，不混在一起

生成界面的视觉由三层决定，改哪层、谁负责，必须先分清：

### L0 · 结构语言（跨宿主一致，不随主题变）

| 项 | 规则 | 依据 |
| --- | --- | --- |
| 字阶 | 正文 14/22 · 模块标题 18/26 · 辅助 12/18 · 数字 20/28 | 02-VI §3、19 §5 |
| 字重 | 只用 400 / 600，**禁止 700** | 02-VI |
| 间距 | 4 / 8 / 12 / 16 / 24 五档；卡内 16，卡间 12 | 02-VI §5 |
| 圆角 | 卡片 12 · 控件 8 · 胶囊 999 | 02-VI |
| 边框 | 1px；分隔线只用 `--border-l1` | 现状 |
| 图标 | 16 / 20 / 24，线宽 1.6，只用登记图标 | 02-VI |
| 密度 | 正文行宽 ≤ 74 字符；表格行高 44；控件高 36 | 03-功能与交互 |
| 动效 | 只允许 ≤160ms 的透明度/位移；禁打字机/闪烁/装饰动效 | 宪章八、19 §5 |

### L1 · Token 映射（随宿主变，组件不写颜色）

- **结构色**（背景/文字/边框/状态）：对话端用 `--dsw-alias-*`；工作台端用 `--ws-*`。组件 CSS **只引用语义变量**，不出现 hex。
- **数据色板（本次要新增）**：图表/地图/分类不能继续用黑白灰。建议引入 6 个语义数据色，映射到宿主已有的 static 色（**不新增品牌色**）：

| 变量 | 亮色映射 | 暗色映射 | 用途 |
| --- | --- | --- | --- |
| `--oui-series-1` | `--dsw-static-deepseek-500` | `--dsw-static-deepseek-450` | 主序列 / 路线 |
| `--oui-series-2` | `--dsw-static-blue-500` | `--dsw-static-blue-400` | 次序列 |
| `--oui-series-3` | `--dsw-static-green-500` | 同左 | 正向 |
| `--oui-series-4` | `--dsw-static-amber-500` | 同左 | 注意 |
| `--oui-series-5` | `--dsw-static-red-500` | `--dsw-static-red-400` | 风险 |
| `--oui-series-6` | `--dsw-static-neutral-bluish-400` | `--dsw-static-neutral-bluish-600` | 其他/基准 |

工作台端把同名变量映射到工作台 VI（沉墨/纸白/单一主色），**组件代码零改动**。

### L2 · 组件视觉规则（逐组件，确认后写死）

- **Card**：`--dsw-alias-bg-layer-1` 底 + `--border-l1` 边 + 12 圆角 + 16 内边距 + 标题 15/22/600。
- **Badge**：胶囊、内联尺寸（**修掉现在被 Row 拉满的 bug**）、只描边不填充、tone 只染文字与边。
- **Button**：高度 36、圆角 8；主按钮用 `--brand-primary`；次按钮描边；文字 13/20/600。
- **Table**：表头 `--bg-layer-2`、行分隔 `--border-l1`、单元格 13/20、首列 600、数字右对齐。
- **Chart**：网格 `--border-l1`、轴标签 12/18 `--label-secondary`、序列用 `--oui-series-*`；**禁止默认黑柱**；≤12 条时补文字图例。
- **Map**：瓦片降低饱和度（滤镜）或离线示意网格；路线用 `--oui-series-1` 2px；标记 12px 圆点 + 1.5px 白描边；标注 12/18。
- **Timeline**：左侧 1px 竖线 `--border-l1`，节点 8px 圆点，时间 12/18 `--label-secondary`。
- **Form**：控件 36 高、圆角 8、聚焦环 2px `--brand-primary` 40%；标签 12/18。
- **Tabs**：下划线式，选中 600 + 2px 下划线；不填充背景。
- **Callout**：左侧 3px 语气色条 + 8% 透明底；不用整块彩色。
- **Gallery/Image**：16:9 或 4:3 固定比例，圆角 12，失败占位是"灰底 + 一句说明"，不出现破图。
- **空/加载/失败**：骨架 3 行；失败一句人话 + 一个下一步；统一在 `.oui-empty`。

## 2 · 组件分层与缺口规划

### 2.1 现状（v1 已实现 21 个，功能全通）

| 层 | 组件 | 状态 |
| --- | --- | --- |
| 基础 | Text / Heading / Badge / Divider / Code / Callout | ✅ 有，视觉待按 §1 L2 收口 |
| 布局 | Stack / Row / Card | ✅ 有，Row 的 flex 规则要修 |
| 数据 | Stat / Table / Chart / Timeline / List | ✅ 有，Chart 配色与布局要重做 |
| 媒体 | Image / Gallery / Map | ✅ 有，Map 可用真实瓦片，需降噪与标记规范 |
| 交互 | Tabs / Form / Buttons / Chips | ✅ 有，状态与禁用规则要对齐宿主 |

### 2.2 建议补的组件（分两批，单独考虑，不阻塞本轮）

**v1.1 基础补齐（对话 + 工作台都要用）**
1. `Progress` / `Steps`：多步计划与任务进度（工作台"卡在哪"要用）。
2. `Accordion`：长内容折叠（避免一次堆太高）。
3. `Segmented` / `FilterBar`：视图切换与筛选（看板场景）。
4. `EmptyState`：缺数据时"缺什么 + 下一步"（四态统一）。
5. `KeyValue` / `DefinitionList`：字段清单（项目/任务详情高频）。

**v1.2 工作台语义层（复用 18 号模板，不进对话自由生成）**
6. `ViewHeader`：出处条（AI 生成 · 依据 N 条 · 数据截至 …）。
7. `EvidenceBar`：依据三态（有依据/无来源/待核对）。
8. `JudgmentCard`：判断卡（结论/依据/不确定性/何时成立）。
9. `RiskMatrix`：风险 × 证据强度矩阵。
10. `BlockerChain`：阻塞链（卡在哪、等谁、下一步）。
11. `ResponseBar`：四回应（同意/不同意/稍后再决定/改写）。
12. `ProjectCard` / `TaskRow`：工作台列表原子。

> 原则：**对话端只开放前 5 个 + 现有 21 个**；语义层 6–12 只在工作台模板里出现，避免模型自由生成"看起来像工作台对象"的假数据。

### 2.3 组件契约（两端复用）

- 单一来源：`ui-kit/components.json`（组件名 / 参数形态 / 上限 / 语义层）+ `ui-kit/oui.css`（全部视觉规则）。
- 对话端：React 渲染器（现有 `src/renderer.mjs`）读同一份定义。
- 工作台端：DOM 渲染器读同一份定义；两端产出的 DOM 必须同构（同 `oui-*` 类名、同 `data-*` 标记）。
- 门禁：①两端同 DSL 输入 → DOM 结构快照一致；②token-only（禁 hex/rgb）；③字阶白名单；④对比度 ≥4.5:1；⑤390 无横向溢出；⑥暗色无硬编码色。

## 3 · 必须先拍板的架构问题：界面放哪里

实测（2026-10-18 14:10）：`tool.call.toolview` 能渲染，但工具调用在 Chat 里被折进"过程组"（"执行了命令，已调用工具，已读取文件等"），**默认看不见**；要"回答即界面"必须换呈现位置。三种方案：

| 方案 | 做法 | 像 ChatGPT 程度 | 成本/风险 |
| --- | --- | --- | --- |
| A 保持工具卡 | 用户点开过程组才看到 | 低（更像"查看详情"） | 最低，已完成 |
| B 回合末尾直接展示 | 用 `conversation.chat.turnTail` 在回合结束处渲染 | 中高（回合完成即见） | 中：需把 render_ui 参数接进 turn 数据；流式阶段看不到 |
| C 自定义会话事件行 | 注册 `uiConversation.events` 定义，在步骤外新增一等公民行 | 最高（边生成边见） | 高：要摸清 snapshot/Location 契约，版本耦合 |

**建议**：v1 选 **B**（可见、稳定、成本可控），C 作为 v1.1 评估；A 保留为降级（turnTail 不可用时）。
