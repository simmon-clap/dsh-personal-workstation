### 1.1 安装方式偏离（必须披露）

`plugin_manager install_bundle` 第一次失败：

```
[ERR_PNPM_UNEXPECTED_STORE] Unexpected store location
dependencies at ~/.dsh/profiles/desktop/node_modules are linked from .../store/v10
pnpm now wants to use .../store/v11
```

- 根因：DSH 内置 pnpm **11.28.5**，而 profile 的 `node_modules` 是系统 pnpm **10.6.1**（store v10）装的；管理器不提供 `--store-dir` 覆盖入口。
- 处理：**先用系统 pnpm 10.6.1 在 profile 里 `pnpm add --ignore-scripts "file:…/智能界面"`**（与现有 store 匹配），再用官方 `plugin_manager set_bundle enabled=true` 选择 bundle 并触发热重组。安装前后已备份 `package.json` / `pnpm-lock.yaml`（见 §6）。
- 影响：profile 依赖列表多一条 `file:` 依赖；bundle 选择走的是官方通道，回滚只需 `set_bundle false` + 删依赖。
- **风险**：这是绕过官方安装器的临时办法；等 pnpm store 升级或管理器支持 store 覆盖后应恢复官方路径（记入 28 §7）。

方法：无头浏览器打开正在运行的会话，每 120ms 轮询 `[data-oui-phase]`；同时发一张 34 组件的自检卡（"流式渲染自检"）。

| 4.49s | preparing | 7 | 11 |
| 5.37s | preparing | 13 | 19 |
| 6.14s | preparing | 19 | 27 |

## 6 · 已知缺陷与未验证

### 6.1 呈现位置（阻塞"回答即界面"）

- 工具调用被 Chat 折进"过程组"（"执行了命令，已调用工具，已读取文件等"），**默认看不见**；要用户点开。
- 三种方案与推荐见 [20 §3](20-生成式界面VI与组件规划-讨论稿-20261018.md)（B 回合末尾 / C 自定义会话行）。
- 在拍板前：卡片仍按工具卡渲染，截图需从 DOM 取出（方法已写成脚本）。

### 6.2 视觉缺陷（等 V1/V2 拍板后修）

图表纯黑柱、刻度带单位拥挤、X 轴标签截断；整体黑白灰层级平；地图标记压地名、暗色瓦片过亮；Tab 选中态弱；Gallery 外链失败时占位文案停在"图片加载中…"。

### 6.3 未验证项

- 真机 iOS / Android（只验了 Chrome 无头 390 视口）；
- 企业代理 / 离线网络（地图瓦片与图片外链会失败；已设计退化，但未在断网下实测）；
- 大卡性能上限（200 节点、32k 字符的渲染耗时未测）；
- 多实例并发（同一台机器多个 DSH 实例下的行为未测）；
- 官方 `install_bundle` 路径（受 pnpm store 版本阻塞）。

### 6.4 模型生成可靠性（真实发现，需在 V4 组件规划里继续收敛）

- 同一句"生成一张含 Chips/Form/Buttons 的界面"的提问，5 次真实运行里有 **2 次**模型产出越界/缺字段（errors 8–13），失败卡片会被渲染成失败态。
- 已做的缓解：①Host 把"有可渲染内容"与"完全合规"分开——部分越界不再整卡失败，而是渲染可用部分并把警告回给模型；②提示词允许"校验失败后修正重试一次（最多 2 次）"；③验收脚本用固定源码隔离渲染与交互。
- 尚未解决：模型仍可能一次失败就结束（不重试）。这是产品风险，需在组件范围（V4）里通过"更小的组件集 + 更明确的示例"降低，而不是靠验收脚本绕过。

## 7 · 回滚与恢复

**演练记录（2026-10-18 14:2x，真实实例）**

| 步骤 | 命令 | 观察 |
| --- | --- | --- |

| 动作 | 命令/位置 | 影响 |
| --- | --- | --- |
| 关闭插件（保留包） | `plugin_manager set_bundle target=dsh-intelligent-ui enabled=false` | 立即卸载 Host 工具/提示词/Client 视图；已存在会话里的 `render_ui` 调用退化为通用工具卡（不丢数据） |

| 回滚 Host 半 | 需要重启 DSH（Host 模块在启动时加载） | 关插件即可避免重启 |
| 会话数据 | 工具参数在会话日志里；禁用插件不会删除 | 重装后可重放 |

## 8 · 与 ChatGPT Intelligent UI / OpenUI 的能力对照（结论）

| 能力 | ChatGPT Intelligent UI | OpenUI（参考实现） | 本插件（DSH） |
| --- | --- | --- | --- |
| 模型输出 UI | 闭源 | 行式 OpenUI Lang | 行式 DSL（`id = 组件(...)`，root 入口，前向引用） |
| 渐进渲染 | 是 | 是 | **是**（真实实例：1→33→34 组件，§4） |
| 组件范围 | 产品内置 | 自定义组件库 + Zod | 21 个白名单（布局/文本/数据/媒体/交互） |
| 交互回传 | 应用内动作 | onAction / 表单 | 仅 send（发送消息）与 open（http(s) 链接） |
| 任意模型可用 | 否（自有产品） | 是（换模型只换配置） | **是**（工具调用型模型都能用） |
| 数据诚实 | 产品级 | 取决于组件 | 提示词硬约束 + 只允许真实 URL + 上限截断；**不做自动事实校验** |
| 持久化/重放 | 对话历史 | 应用自管 | 工具参数进 Session 日志，重放/fork 可重建 |
| 主题 | 自有 VI | 自定义 | 跟随宿主 token（亮/暗/字号），组件零硬编码颜色 |
| 移动端 | 有 | 有 | 390px 无横向溢出（实测 4 卡） |
| 安全边界 | 闭源 | 组件库受限 | 不执行任意代码、不渲染自由 HTML、不写业务库 |
| 与工作台复用 | 不适用 | 不适用 | **设计为一份 DOM 契约 + 两套 token 映射**（未实现，见 20） |

**能复刻的**：交互范式（回答即界面、流式、可点）、任何模型可用、主题跟随、可重放。
**复刻不了的**：ChatGPT 的闭源组件与地图/图片资源、像素级一致、其模型侧产品能力。
**边界**：本插件是"对话内的受控界面层"，不是通用低代码/自由 HTML 平台；工作台页面内生成视图仍走 18 号 `view` 对象那条线；两者共用组件契约而不是共用渲染器。
