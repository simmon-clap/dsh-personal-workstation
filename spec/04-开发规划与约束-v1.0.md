## 0 · 开发目标

> **按宪章把工作台从"事务型台账"推进到"判断型工作台"，并让助理具备受约束的主动性。**

**完成定义（DoD）**：以下五条全部成立才算完成，缺一条都算未完成。

1. 宪章第三条（判断是一等公民）与第四条（建议必须闭环）**全部可用**，并有真实业务数据证据；
2. VI 门禁 12 项**全绿**（含精致一致性）；
3. 心跳按平衡机制运行：出声分级、额度随反馈涨落、双向计量、免打扰窗口有效；
4. 界面词汇**零新增**，全部在登记表内且过四道直觉测试；
5. 每批账本完整：做了什么 / 没做什么 / 证据在哪，不掩饰。

**明确不在本轮目标内**：多人协作、组织权限、第二套模型入口、外部日历/钉钉 API、票据识别、无上限全量画布。

## 2 · 三条不可违背的约束

### 约束一 · 依据门
**本批每个改动都必须能指回一个 F 编号与一条宪章条文。**指不回去的，不做 —— 不是"以后补文档"，是当场不做。

### 约束二 · 不自行设计
- **不新增、不删除、不重排任何入口。**信息架构改动属于范围变更，必须先讨论。
- **不新增对象类型、颜色、图标、界面词汇**，除非先登记（见批次 0 的登记表）并过四道直觉测试。
- **不重组界面、不另起一套视觉。**界面基线是冻结的 V7 原型切片；视觉基线是本目录 02 文档。
- **不静默修改宪章。**发现冲突必须先停下报告。

### 约束三 · 未接入不伪造
- 没接通的能力写"未接入"，不给假按钮、不给假进度、不给假成功。
- 只有真实回执才可说"已保存"。**即时响应允许（丝滑），无回执的假成功禁止（违反宪章）。**
- 网络重试复用同一幂等键；冲突不静默覆盖。

## 3 · 分批计划

每批必须完整走完"依据 → 实现 → 门禁 → 证据 → 记账"才进入下一批。**禁止跨批混改。**

### 批次 0 · 护栏（必须先做）
- **依据**：宪章第九条 + 本约束。
- **产出**：`spec/registry.json`（登记：颜色、图标、入口、对象类型、界面词汇、组件实现）；`workstation/prototype/charter-guard.mjs`（守卫脚本：扫描未登记的颜色/词汇/入口/间距/字号）；`workstation/进度账本.md` 模板；把守卫并入 `npm run verify`。
- **验收**：守卫脚本对现有代码**报出真实的违规数**（不必为零，但必须真）；人为注入一条违规能被抓到（`--self-test`）。
- **不跑偏要点**：先有护栏再动功能，否则几十小时后无法判断是否偏离。

### 批次 1 · 判断对象（F6 / F8 / F9）
- **依据**：宪章第三条；交互律 06、09；VI V2。
- **产出**：判断的存储与校验（字段契约见 [03 文档 §10](03-功能与交互设计-v1.0.md)）；依据回链到会话原文/文件/录音片段；推翻留痕；判断卡的界面（依据就地展开，不跳页）。
- **验收**：真实会议材料 → 沉淀判断 → 每条依据可点回出处 → 标记待复核 → 被新证据推翻后旧判断与理由仍可查。
- **不做**：不做"关于你的理解"页面（宪章第四条已明确不建档案）。

### 批次 2 · 待核对（F7）
- **依据**：宪章第三条；交互律 02；VI V4。
- **产出**：判断上的"不确定/待核对"聚合为**筛选视图**；勾选核对后就地改写该条的不确定性说明。
- **验收**：能在判断列表上筛出待核对；核对后不确定性文字被更新；**没有新增任何入口**。

### 批次 3 · 建议闭环 · 规则与数据（F10–F14 后端）
- **依据**：宪章第四条；交互律 07、08。
- **产出**：建议的状态机（待你决定/已采纳/已改写/已否决）；理由记录（改写/否决必填一句）；"为什么这么建议"的取数（参考了哪几条判断与理由，取不到就标记通用建议）；采纳情况统计；被否决不复活。
- **验收**：一条建议从待决定 → 采纳/改写/否决全程有回执可撤销；否决理由被持久化并在下次相关建议上被取到；无支撑建议被正确标记为通用建议。

### 批次 4 · 建议闭环 · 界面（F10–F12）
- **依据**：宪章第四条；交互律 07、08；VI V3。
- **产出**：建议卡四回应全在卡上；改写/否决就地出现一行输入框；否决后卡片转灰墨**留在原位**；可展开「为什么这么建议」。
- **验收**：零跳页完成四回应；否决理由一句话即可提交；否决卡不消失。

### 批次 5 · VI 落地与精致（V1–V3、V9）
- **依据**：02 文档全篇；宪章第六条。
- **产出**：来源三态；判断三要素视觉；建议四态视觉；宿主主题变量核实（02 §12：前缀 `--dsw-alias-*`，**变量名须先核实**）；组件唯一实现收敛；四态补齐；间距与字号收敛到标尺；清理 `!important` 覆盖；消费宿主主题变量。
- **验收**：VI 门禁 12 项全绿（含 `audit:craft`）；对比度明暗两套逐文本节点 0 处不达标。

### 批次 6 · 拿出来（F15–F18）
- **依据**：宪章第一条第 2 句、第二条；交互律 10；VI V7。
- **产出**：十年检索；判断导出（自带出处与时间）；分享默认仅自己；导出前显示"将分享 N 条 · 剔除 M 条仅自己"；记忆治理补来源三态。
- **验收**：导出一份文档，收件人无需解释即可看懂哪条是谁在何时判断、依据是什么；剔除项被明示。

### 批次 7 · 主动 · 做事与留痕（F19–F22、F24）
- **依据**：宪章第六条补充；交互律 11、12。
- **产出**：四类心跳任务（守承诺/盯依赖/做简报/复核旧判断）；留痕；最后成功时间；连续失败告警。
- **外部依赖**：**真正的定时需要常驻节点上线**。本批先实现判定逻辑与留痕，用现有 profile 手动触发验证；不得声称"已在定时运行"。
- **验收**：手动触发后留痕如实记录"看到什么、为什么不打扰"；模拟失败能产生告警。

### 批次 8 · 主动 · 出声（F23）
- **依据**：宪章第六条补充；交互律 11、12；03 文档 §6。
- **产出**：出声四级；额度（由反馈涨落，不出声不涨）；三扇门；双向计量（含"该说没说"）；免打扰窗口；二级出声道飞书一条消息。
- **验收**：额度初值 40，标为"没必要"后降到 30 及以下；窗口内零出声；二级出声同时满足三条件；标记"该说没说"后门槛下调一档（初值与幅度见 [03 文档 §11](03-功能与交互设计-v1.0.md)）。
- **外部依赖**：飞书出声复用 IM 助理渠道，**接口与载荷须核实**；核实前二级出声降级为一级，不得声称已能推送。

### 批次 9 · 终验
- **依据**：03 文档 §9 八条判据 + 宪章六个检验判据。
- **产出**：逐条验收报告 + 真实浏览器证据 + 账本收口。

### 助理后台 · 三批（宪章 v1.4 新增，2026-10-21）

不编新批次号（避免与既有批次交叉引用冲突）；**顺序即依赖，不得并行**。

#### 后台 1 · 接住（不漏）
- **依据**：宪章 v1.4 第二条（事事有回应）· 03 §13（v1.1）
- **产出**：收件本（`intake`）+ 五个入口各加一行承接 + 「没人接」清单
- **验收**：真实走过五个入口，每条输入都有归属；人为制造一条无归属 → 清单能列出
- **不做**：不动任何现有表结构；每个入口单独上、单独验（回归风险最高的一批）

#### 后台 2 · 着落（不悬）
- **依据**：宪章 v1.4 第二条（件件有着落）
- **产出**：终态四档（完成 / 放弃 / 转出 / 在等谁到何时）+ 超期无终态扫描（接进心跳）
- **验收**：能列出所有悬空项及其「在等谁」；超期项进心跳留痕并写明为什么没打扰

#### 后台 3 · 判断（够深）
- **依据**：宪章 v1.4 第六条补充 · 03 §6 ⑨（三问判据）
- **产出**：候选 → 三问过滤 → 两个开口点（早/晚）；不说的写理由
- **验收**：每条出声都能回答三问；被过滤的进留痕并写明**缺哪一问**
- **外部依赖**：出声通道见批次 8；本次不接新通道

> 三批之间**只做加法**：任何一批停下，系统都还能用——这是"不重构"的可验证判据。

## 4 · 防跑偏协议

### 开工前（固定顺序，不得跳步）
1. 读 [01-顶层宪章](01-顶层宪章-v1.0.md) —— 校准立场；
2. 读本文件 §3 中**本批**那一条 —— 确认依据、范围、验收、不做；
3. 读最近 3 条账 —— 确认上一批真的收口了；
4. 确认 `git` 或备份点存在，且工作区干净。

### 每批三条硬门（不过不进下一批）
| 门 | 判据 |
|---|---|
| 依据门 | 本批改动逐条能指回 F 编号 + 宪章条文 |
| 概念门 | 无新增界面词汇；若必须新增，先登记 + 过四道直觉测试 |
| 精致门 | 新控件复用唯一实现、四态齐全、间距字号在标尺内 |

### 完成门
- 本批验收标准**逐条**通过；
- 相关门禁脚本全绿（`verify` + 本批新增门禁）；
- **真实浏览器 + 真实数据**证据（截图/日志），不接受"仅单测通过"；
- 账本已写（做了什么 / 没做什么 / 证据在哪）。

### 偏离即停（出现即停止编码，先报告）
1. 需要新增对象类型、入口、颜色、图标或界面词汇；
2. 需要修改宪章、VI 规范或本规划的任何条文；
3. 需要改信息架构或重排导航；
4. 发现宪章条文与现有实现直接冲突；
5. 需要外部凭证、地址或设备（如常驻节点、日历身份）；
6. 单批耗时超过预估 **2 倍**；
7. 门禁出现无法解释的失败；
8. 发现自己正在"顺手"改一件本批范围外的事。

**停下时给出的格式**：现象 → 证据（文件/行号/截图） → 可选方案（≥2） → 我的建议 → 影响面（哪些已验收批次会受影响）。**不要只问"怎么办"。**

## 5 · 连续工作节奏（几十小时）

- **每批 2–4 小时**；批间不停，但**每批结束必须记账**（哪怕只是三行）。
- **每完成 3 批做一次对齐自检**：重读宪章九条标题 + 检查是否出现新的自发概念/入口 + 检查登记表是否被绕过。
- **禁止跨批混改**；**禁止在未验收的批次上叠加新批**。
- **上下文丢失后的恢复顺序**：04 → 01 → 本批验收 → 最近 3 条账 → 再看代码。**不允许凭记忆继续改。**
- 每次改完必须重启 DSH 才能验证生效（启动型 profile）；**"安装成功"不等于"已加载"**，必须核实运行版本。

## 6 · 必须停下来问用户的情况

除上文"偏离即停"8 条外，还包括：

- 要动宪章、VI 或本规划的任何条文；
- 要让某项功能"先简化以后再补"而又涉及宪章条文；
- 上游文档与实现冲突（例如文档说"工作区选择"，实现已删除）；
- 任何可能让用户看到的界面行为改变（文案、入口、状态），而 03 文档没有覆盖。

## 7 · 不做清单（写下来防漂移）

- 不重建界面、不重排导航、不自行增删入口；
- 不新增颜色/图标/对象类型/界面词汇（未登记即不做）；
- 不做"关于你的理解"这类常驻档案页；
- 不做乐观 UI、不做装饰性动效、不做情绪化提示（红点、感叹号催促、成功撒花）；
- 不用模型置信度替代授权；不无授权读写；
- 不把接口规划写成已实现；
- 不做无上限全量画布；
- 不为"通用化/给别人用"付出设计成本（定位是长期自用）；
- **不做工作区选择或空间切换** —— 沿用已拍板契约：数据只跟根目录走（`rootDirectory`），整库一份；「空间与设置」里的目录/知识库授权是**授权**，不是切换当前视图；
- 不因为某个功能需要而顺手改宪章。

## 8 · 门禁与证据要求

| 类别 | 必须 |
|---|---|
| 单元/集成测试 | 新增行为必须有测试；测试数量不作为进展叙事 |
| VI 门禁 | 02 文档 §13 的 12 项，含 `audit:craft` |
| 交互门禁 | `audit:interaction`（红色必须为 0） |
| 文案门禁 | `wording-audit`（禁造词表已并入 03 文档 §7） |
| 构建门禁 | Config 加键必须同步 `resolveConfig` 白名单；工具返回值必须无损 JSON |
| 发布门禁 | 校验**真正要安装的 tarball**；安装后核实运行版本 |
| 视觉证据 | 真实浏览器截图（桌面 1440 / 手机 390 两档），亲自走用户会走的入口 |
| 记账 | `进度账本.md`，含"没做什么" |
