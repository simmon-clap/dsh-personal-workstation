## 一 · 分层与编号规则

**四层，段位固定**：编号第一位是层，第二位是序。**编号唯一，不得复用。**

```
0x · 宪章        只定义不可让渡的。功能推导不出来的，不做。
1x · 规范        跨项目的最高约束。改它要走宪章第九条流程（讨论→记版本与理由→旧文归档）。
2x · 方案        具体设计与方案。可随实现演进，但不得违反 0x／1x。
3x · 手册        操作性文档。照着做就能完成一件事。
4x · 记录        审计、验收、账本。**只追加，不改写**（改的痕迹会让记录失去证据价值）。
```

**四个约束方向**（从上层到下层单向）：

```
0x 宪章  ──约束──▶  1x 规范  ──约束──▶  2x 方案  ──约束──▶  代码
   │                     │
   └──────4x 记录────────┘   ← 记录**评判**上层，但不修改上层
```

**新文件怎么编号**：先定它属于哪一层，在该层取下一个未用的序号。**不得跳层、不得插号。**

## 三 · 每份规范头部必须有的三样

| 项 | 为什么 |
| --- | --- |
| **依据** | 它由宪章的哪一条推导出来；推导不出来的，不该存在（宪章序：推导不出来的不做） |
| **状态** | 讨论中 / 冻结。**冻结**意味着改动要走流程 |
| **修订记录** | 版本、日期、改了什么、**为什么**。没有理由的修订视为未发生 |

**已固化为门禁**：`spec-headers` —— 缺任一项就红。


## 五 · 门禁与规范的关系（一条硬规则）

> **规范在没有门禁之前，只是一段愿望。**

所以每条规范都要**声明责任人**：要么挂一道在 `npm run verify` 里跑的门禁，
要么写清"人工看什么"。**留白等于没人管** —— 已固化为 `spec-coverage-audit`。

它已经抓到过我两次：
- 我给动效门禁挂了一条**不存在的条款**（`VI · 10 · 动效`，VI 里 10 其实是"分享与导出形态"）
- 规范对照表里有条款而规范里已删除（表腐烂）
