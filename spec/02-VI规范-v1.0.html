00 / 与宪章的关系

VI 不是审美选择，是品味的物质化

本规范由《顶层宪章》第六条推出。宪章九条是立场，本规范是它的视觉投影 —— 视觉上的每一个取舍，都能指回某一条品味。指不回去的视觉元素不做。

品味（宪章第六条）视觉后果
诚实状态不靠颜色单独表达；未接入就是灰字说明；推断用虚线 + 文字
安静无红点、无夺目动效、无装饰性渐变；信息在场但不喧哗
克制一个视图一个主色按钮；不新增颜色、图标、容器
有重量回执与撤销常驻；过渡 120–220ms、位移 ≤ 8px
耐用系统字体、可编辑 SVG、CSS 变量；不绑死宿主实现
精致同一控件唯一实现；同层级同字阶；间距只用标尺；四态齐全
v0.1 评估结论，本版已补齐：原方案对"品味"符合度高，但对宪章第三条（判断是一等公民）与第四条（建议必须闭环）没有对应视觉语言 —— 那是"事务型工作台"的 VI。本版通过 §9 与 §14 的 V1–V3 补齐，并把 V9（精致）纳入 §15 的 12 项机械门禁。

02 / 色彩

大部分留白，小部分有色

唯一色值来源是 design-system/tokens.json。代码里不得出现字面色值。常规页面配比建议：中性空间 ≈85%、文字与线条 ≈10%、行动色 ≈5%。点击色块复制色值。

使用规则

蓝色只承担行动与聚焦；其余颜色只表达真实状态或对象类型。
颜色不得单独承担判断：绿点必配"已完成"，赭色必配原因文字，虚线必配"AI 判断"。

对象与状态编码

项目 · 蓝 任务 · 绿 知识／记忆 · 紫 事务 · 赭
✓ 已完成 Ⅱ 等待输入 ! 执行失败 ◇ AI 待确认

V5 新增准入：新颜色必须对应一个全新的真实状态，且必须同时有文字与符号。不允许为了好看而加色。

13 / 宿主主题

V6：不越权改主题

插件必须消费宿主主题语义变量，不自行发明一套主题映射。 目标前缀 --dsw-alias-*（来自既有审计记录）。具体变量名必须在宿主实现中核实后写入本节（核实方式：在真实页面枚举 --dsw-* 变量，或读取宿主主题样式表）。核实之前不得声称"已消费宿主主题"。

迁移期允许保留 --ws-* 作为变量层，但最终色值来源必须是宿主语义变量 + tokens。
禁止用 !important 覆盖原型内联色（实现层现有 3 处须清理）。

本页右上角的"深色预览"演示的是变量层效果；正式插件接入宿主主题后，深浅切换应交由宿主控制。
