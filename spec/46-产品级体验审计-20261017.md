## 0 · 结论先行

**判定：未达到产品级。** 问题不是"功能数量不够"，而是**体验的最后一公里**与**助理的认知层**没有做：

- 功能对象、变更治理、审计、判据、导出、同步这些"骨架"是扎实的；
- 但用户每天真正看到的界面，字阶是塌的、组件各长一套、设置页像一份 3.4 屏的后台文档、选文件夹会直接报错、任务页把唯一有内容的"待办"藏在第 4 列、手机上首屏看不到一条任务、画布默认 44% 文字 5.7px；
- Agent 目前是**诚实的录入/约束/留痕层**，不是理解层：真实数据里 11 条建议全部在几秒内被"采纳"、`basedOn` 0/11、改写/否决 0、出声反馈 0；7 条判断是 10-16 从 10-12 已写好的纪要结论批量搬进对象，不是从新材料新推出来的；
- 飞书频道不是"一个 bug"，是**四层叠加**：最致命的 L0 是 DSH 升级后 IM 插件因版本不兼容根本没加载（插件管理显示"异常"），其次是飞书 21001 平台访问控制、channel cwd 指错工作区、工作台设置页把"飞书未配置"当成结论展示。

**按 04 §0 的 DoD 五条：0 条完整成立。** 按宪章六条检验判据：2 条强（3、4）· 3 条部分（1、5、6）· 1 条不成立（2，手机首屏完成不了"看→判断→决定"；45 审计当时判"部分"，本轮实测更严）。这与 [45 审计](45-对外发布就绪度审计-20261017.md) 的"可发布但不产品级"并不矛盾——45 审的是**发布物是否合格**，本报告审的是**打开以后好不好用、像不像助理**。

**门禁全绿证明的是"逻辑对、没撒谎"；它证明不了"好用、好看、像助理"。** 这次审计里最刺眼的问题，大多不是门禁红，而是门禁根本没有判据：字阶"在标尺内"就算过（不管层级）、组件唯一只登记 2 个签名、弹窗五条一条不查、图标册为空、`pixel-diff` 阈值失效。用户不需要知道这些，用户只知道"看起来粗制滥造"。

## 1 · 用户点名的五个问题：逐条核实

### 1.1 VI 视觉规范"很多细节粗制滥造"——成立

**规范骨架大体达标，坏在"体系没有落到可见层"。** 先说不该冤枉的：

- 间距标尺（4/8/12/16/24/32/48/64/96）基本守住；侧栏 204、顶栏 76、页边距 32、弹窗 760×88vh、圆角 8/12/20/999 均符合 §4；
- 明暗两套逐文本节点做透明合成后，**对比度 0 处不达标**（浅色最低 4.66:1、深色 6.39:1），深色主题整体可用；
- 8 个简笔画均 240×160 / 2px / 墨色+单一蓝；没有 emoji；每屏实底主色按钮 ≤1；
- 32px 数据数字用了 `tabular-nums`，字重 550；卡片 12px 圆角 + 1px 边框 + 24px 内边距，都在规范内。

真正让用户觉得"粗制滥造"的是四类：

**① 字阶塌陷（最根本）**

- 全站没有 14/22 的正文档，也没有 18/26 的模块标题档；`body` 是 13px/20.8。11px 在可见文本中的占比：**日程 90%、项目 83%、总览 72%、知识 68%、任务 53%**。
- 页面 h2 是 15/600，知识卡标题也是 15/600，两者完全同款；项目卡 h3 是 15/**700**，比栏目标题更粗。全站 700 字重共 15 个实例（项目卡、新闻标题、日历月份、设置值标签）。
- 结果就是"看不出哪级是标题，整页像缩印本"——这不是审美偏好，是 VI §3 和 V9"同层级同一套字阶"没有落地。证据：`11-总览指标散落.png`、`10-知识页判断卡.png`。

**② 组件各页各长一套**

- 按钮：实测 6 种高度（39/29/36/42/32/26）、3 种"次级"长相（白底灰字、白底蓝字蓝边、主色实底）；`#create` 明明 class=primary 却渲染成白底蓝字。规范说"三档、每档唯一"，实际是"同一控件多个变体"。
- 标签：`.chip` 11px/36px 高 + 边框，任务项目标签 `.tag` 11px 无边框，`.tagline` 纯文本，`.statusdot` 8px 圆点——四套。
- 输入：知识页搜索框是浏览器原生 `input[type=search]`（320×41、圆角 0、2px 边框），画布搜索是 164×39、圆角 8、1px；深色下原生框变成纯白块。
- 空态：收件箱 = 简笔画 + 一句 + 一个下一步（达标）；任务看板三列只有一句"当前没有任务"（无图无下一步）；总览用 68px 大圆环"–"（0 进度还因 `stroke-linecap:round` 留了一个假蓝点）。
- 图标：尺寸实测 14/16/17/20/28/33/68，线宽 1.65（规范 1.6、16/20/24）。17px 的任务行 chip 图标是很具体的"没按标尺"。

**③ 占位数据/调试信息直接漏在页面上**

- 7/7 页顶栏副标题都是同一句"项目、任务、知识与事务 · 总览提示"，与当前页无关；`#subtitle` 是外壳里写死的。
- 项目页"交付与阻塞分布"：明明"尚无交付项"，却画了一条满宽 `#EDF2FF` 蓝条；卡底还写"已完成 / 全部交付项：未采用主观'健康分'。"——这是设计争论，不是用户语言。

### 1.2 交互复杂、不直觉——成立

**设置页（用户点名最多）**：一个 760×827 的居中弹窗，内容 `scrollHeight 2841 / clientHeight 825 = 3.44 屏`（手机 5.08 屏），串了 6 个 h2 段 + 7 个 `<details>`：版本说明、数据根目录、定时与提醒、写入审批、7 行能力、5 行外部集成、5 条解释、心跳留痕、出声反馈、目录授权、版本与设计基线。**首屏能点的只有底栏 2 个按钮**，而它们都不是用户来设置页要做的事。

页内还有三套"定时"事实源，在 3.4 屏里同时说三种话：

- 顶部："定时与提醒 **未接入**（这台机器上没有接入定时服务）"
- 中段小字："现在只能手动触发，**还没有接入定时**"
- 紧接正文："**已在定时运行** / 上次跑成 2026/10/17 18:57 / 一共跑过 13 次 / 距上次跑成已经 2.2 小时 / **要看一下：已经 2 小时没有成功跑过**"

**文件夹（用户点名"无法及时选文件夹"）**：项目「微纳核芯」→ 编辑项目 → 项目文件夹 → 选择文件夹，实测红条：

### 1.4 Agent 是否真的"助理级"——没有

**先给结论：它是一个诚实的录入、约束与留痕层，不是理解层。** 工具面 28 个动作里 0 个"理解/推理"动作；判断、关联、建议全靠底层模型自己调 `draft`。产品没有：对话上下文注入、跨对象总结、矛盾发现、主动追问、记忆检索衔接中的任何一项。

**真实数据比代码更能说明问题**（只读副本）：

- 11 条 AI 建议**全部 accepted**：6 条在 06:59:26–33 的 7 秒内连续点完，4 条在 12:09:42–44 的 2.4 秒内连续点完；0 改写、0 否决、`reason` 0 条、`basedOn` 0/11、`speak_feedback` 0。
- 7 条判断的 7 个 draft 在 **2026-10-16 06:28:47 同一秒**创建；标题/引用逐条对应 10-12 已落盘的会议纪要 §4/§5（纪要 mtime 10-12 09:52）。**这是把旧摘要搬进 judgment 对象，不是从原始材料新推出来的判断**；真正有分析含量的是 10-11 那份纪要，产品没有复现那段分析，也没有记录"为什么"。
- 96 个 committed 批次中，按界面口径 **68/96 显示"来源：未记录"**；8 个有 sessionId、11 个只有 `source.kind=advice`（无会话）。

## 4 · 整改建议（按"用户感受收益"排序）

### P0 · 先让它"能用"（建议 1 周内，5 件）

1. **重做设置页的信息架构**（不新增一级入口）：首屏只留"授权（文件夹/知识库）+ 能力状态 + 一个与用户目标相关的动作"；版本/数据根/设计基线收进"关于"；心跳留痕/出声反馈收进"助理替你做过的"折叠；**统一"定时"为单一事实源**（以 heartbeat 定时器真实间隔为准），删掉写死的"还没有接入定时"和三套口径。验收：设置首屏 ≤1 屏、首屏至少 1 个可点且与用户目标相关、全页不再同时出现"未接入/已在运行/手动触发"。
