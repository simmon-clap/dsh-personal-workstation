## 2 · 怎么跑

```bash
cd workstation
npm run gate:semantic            # 真实实例 + 真实数据：桌面 7 视图 + 设置/编辑弹窗 + 画布 + 手机 4 页 + 任务详情
npm run gate:semantic:canary     # 再加：判据离线 canary + 实时注入 canary（证明测量路径会响应）
node --test test/semantic-gates.test.mjs   # 判据逻辑回归（进 npm test / verify 链）
node --test test/pixel-diff-verdict.test.mjs
```

- **不进 `npm run verify`**：`semantic-gates` 依赖正在运行的实例与本机登录凭据，换台机器就跑不了（同 `live-acceptance`）。但**判据逻辑测试**（`test/semantic-gates.test.mjs`）是纯函数，进 verify 链。
- 退出码：任一判据违规、任一 canary 没抓到 → `1`；跑不起来（找不到实例/凭据）→ 打印「不是通过，是没测到」并 `1`。
- 输出：`prototype/screenshots/semantic-gates/`（桌面/手机/弹窗/画布截图 + `semantic-report.json`）。

### 判据的「真」怎么保证（S11 的具体做法）

1. **干净夹具**：`cleanFixture()` 是人工构造的「完全合规」测量数据；10 项判据必须全部 0 违规。任何字段名拼错/阈值量纲错→这里先红。
2. **注入 canary**：`CANARIES` 给每条判据注入一处违规，断言 `before 0 → after >0`；10/10 必须抓到。
3. **实时注入**：`semantic-gates --canary` 在真实页面上真的改 DOM（加 700 标题、加主色按钮、加空环、加第二行导航、改画布 scale、加相邻危险按钮……），断言测量路径真的响应；10/10 必须响应。
4. **反向 canary**：S10 注入四行健康文字后「缺失数」必须下降——证明它既能判「没有」，也能判「有」。

## 5 · 边界与已知局限（不掩盖）

1. **S6 的按钮口径收窄**：只量 `.btn` + 顶栏控制（当前 3 档）。标签页 32、日历 chip 26、导航 42 属于不同控件，混在一起算「按钮高度」会得出错误结论（修错方向）。宽口径的「同一控件多套长相」进 M6 人工检查。
2. **S2 的「筛选默认值」没有机械判据**：收件箱默认「待确认」被算进「筛选 · 1」，机械上无法可靠区分「默认视图」与「用户筛选」；进 M3 人工检查，W2 前补判据。
3. **S10 只判「四行文字在不在」**，判不了「来源是否真实」；后者由 W1 P0-5 实现时逐行核对（M4）。
4. **S9/S13 未机械化**：真实用户路径与助理级判据是「用户能不能完成」「系统是不是理解层」，只能人工验收；在通过前，界面与文档不得自称「助理级」。
5. **测量依赖运行实例**：本清单的「真实违规数」对应当前运行实例（服务端实际发出 `space-view=79bddc59…`，与已装包/仓库 `dc86f7a6…` 不一致——**重启 DSH 后必须重跑**，见账本起点事实）。
6. **只读边界**：`semantic-gates` 只做 GET、点开导航/弹窗、Escape、一次不保存的输入；不点保存/同意/撤销/画布缩放。第一次运行前后 layout revision 57→57、各表计数不变（见基线 metadata）。
