## 0 · 为什么需要它

固定界面的价值是稳定、可比、可审计；代价是答不了"这次的问题"。对话里已经有一类回答**看比读合适**：行程与路线、方案对比、趋势分布、多步计划、表单收集、需要用户点选下一步。这类回答用文字写，用户要读三层才能做决定；做成界面，用户直接看和点。

DSH 宿主已经具备落地条件（2026-10-18 实机核验，证据见 28 号 §3）：

| 条件 | 宿主事实 |
| --- | --- |
| 替换工具卡片 | `tool.call.toolview` 是**按 wire Tool 名分发的 keyed slot**，key 域开放；未注册的工具名回落通用卡片；注册写法 `ctx.slots.register({name:'tool.call.toolview', key:'<wire tool name>'}, Row)` |
| 三阶段 | 注册视图收到 `preparing` / `start` / `result` 三个阶段 props，每个阶段带 `block.name` 与**惰性 `args` 读取器**；`preparing` 读取器随模型输出增长 → 可渐进渲染；旧 `argsRaw` 与 result 的 `call` 字段仍在 |
| 交互回传 | `ui-conversation` 通过 `ctx.uiSession` 提供 `inputActions`（含 `setDraft` / `submit`）等稳定标准 props，会话输入框是唯一发送通道 |
| 注入方式 | Client 半经 `window.__ModuleLoader__.load({factory})` 注入；factory 内只 `require('react')` / `require('styles')`，不得 require 宿主 Client 包 |
| 复用边界 | OpenUI 官方 `@openuidev/react-lang` 的 peer 依赖是 `react>=19`，宿主客户端是 **React 18.2**（MIT 许可），因此 **v1 不引官方运行时**，只借"行式语言 + 白名单组件 + 渐进渲染"架构 |
| 可复现 | 界面源码随 **`render_ui` 工具参数**进入 Session 日志；重放 / fork 用同一参数重建，插件不存业务数据 |

**它不是**：

- 自由 HTML / iframe / 任意脚本（安全与规范双重不可控）；
- 工作台页面里的生成视图（那是 18 号管的对象 `view`，见 §7.2）；
- 聊天记录里嵌一个网页；
- 新的页面、一级入口或第二个模型入口；
- "AI 画的图"当证据。

**与 27 号 D11 的关系**：27 §2 D11 的选项 B（宿主 `openui` 插件线）已经立项为独立产品线。本规范把这条线从"能跑的雏形"收成"可验收的插件"：**定义边界、宿主契约、语言、安全、渲染、复现与验收判据**；开发批次与决策门在 28 号。

## 1 · 范围与不做清单

### 1.1 v1 做什么

| # | 能力 | 一句话边界 |
| --- | --- | --- |
| S1 | 对话内生成式界面 | Agent 调 `render_ui({ui})`，工具卡片位置渲染成可读、可点的组件树 |
| S2 | 行式界面语言 v1 | 一行一条 `id = 组件(参数)`，入口 `root`，前向引用；21 个白名单组件（§3.2） |
| S3 | 渐进渲染与最终校正 | 生成中（preparing / start）按已闭合语句渐进出现；完成后（result）按最终源码校正 |
| S4 | 两类交互回传 | `send`（把文本交给会话输入框发送）与 `open`（新窗口打开 http(s) 链接），**没有第三类** |
| S5 | 四态与降级 | 加载中 / 空 / 失败 / 正常，各有文字与下一步；无 `inputActions` 时在正常态内禁用交互并说明（§5.4、§2.6） |
| S6 | 宿主主题渲染 | 只用宿主 `--dsw-alias-*` token 与固定 5 档字阶；桌面与 390 手机宽度都不横向溢出（§5） |
| S7 | 可复现 | 同一 Session 日志重放 / fork 后卡片可重建；语法 v1 冻结，插件升级不破旧源码（§6） |

### 1.2 v1 明确不做

| 不做 | 原因（依据） |
| --- | --- |
| 不生成工作台页面内视图、不写 `view` 对象、不入库 | 那是 [18](18-生成视图规范-草案-20261018.md) 的渲染面与持久化；两条线不共用渲染器（§7.2；D15） |
| 不跑自由 HTML / iframe / srcdoc / 远程脚本 / 远程样式 / 外部字体 | 宪章八（不做无授权执行）+ 本规范 §4.1 |
| 不调模型、不注册模型入口、不在 Client 侧持有凭据 | 宪章八（第二套模型入口）；单一模型入口 |
| 不执行写操作：按钮不直接改对象、不调用其他工具、不发网络请求（除用户点 `open` 打开外链） | 交互只有 send/open；写数据只能走 Agent 回合（§4.4） |
| 不新增一级入口 / 页面 / 导航 / 会话节点类型 | 17 C4；slot 只换卡片内部，不改 Conversation Node 种类（§2.2） |
| 不做导出、分享、截图留档、跨会话迁移 | 18 号的"存为判断/简报/导出"属于工作台对象；本插件 v1 不承担 |
| 不做真实地图瓦片、不做在线地理编码 | D14；v1 的 Map 只画本地几何（§3.2 / 28 §2） |
| 不做主题自定义、不做字号/颜色配置项 | 视觉只用宿主 token；配置项越少越可预测 |
| 不用 emoji 当图标、不提供图标组件 | 02 VI V9；组件内容由模型按用户语言生成，图标不在白名单 |
| 不把界面当证据 | 可留档的是依据链与文字结论；界面是阅读面（宪章三 / 八） |

## 2 · 宿主契约（基线：DSH 0.2.1-rc.2）

### 2.1 版本基线

| 项 | 事实 |
| --- | --- |
| 宿主版本 | **0.2.1-rc.2**（证据：`/Applications/DeepSeek Harness.app/Contents/Info.plist` 的 `CFBundleShortVersionString`；`app.asar` 内字符串；本机 profile `pnpm-lock.yaml` 对本插件的 engines 约束 `dsh: >=0.2.1-rc.2`） |
| 客户端 React | **18.2** |
| 插件 engines | `dsh: ">=0.2.1-rc.2"`、`node: ">=24"`；宿主版本不满足 → **不加载，不静默降级** |
| 旧口径作废 | 工作台插件线此前按 **0.2.0-rc.2** 写下的宿主 API 结论（含 slot/props/注入方式）**一律作废**；本规范与 28 号以 0.2.1-rc.2 为准 |
| 契约快照 | 每次宿主升级前后，把 `tool.call.toolview` 的注册签名、三阶段 props 字段、`inputActions` 形状记入 28 号证据账本；升级先跑 G1/G2（§8） |

### 2.2 插槽：keyed slot，不是新节点类型

- `tool.call.toolview` 的 **key = wire tool 名**。本插件只注册一个 key：`render_ui`。
- **key 域开放**：其他插件用自己的工具名注册自己的卡片，互不冲突；本插件不注册别的 key、不改宿主 dispatch。
- 命中 key → 该工具调用卡片由本插件渲染；未命中 → 宿主通用卡片。**插件加载失败时用户仍能看到工具调用**（降级到通用卡，不白屏）。
- 本插件**不新增 ChatNodeKind**：Conversation 里仍是普通 `tool-call` 节点；call/result 配对、生命周期、`subCalls` 投影由 Runtime 权威，插件不重建 transcript。
- PTC 派生的子调用按同一 key 规则分发；本插件不依赖 PTC，遇到带 `parentCallId` 的块按普通块渲染。

```js
// Client 半注册（src/client-entry.mjs 现行写法，冻结为契约）
ctx.slots.inject('tool.call.toolview', () =>
  ctx.slots.register({ name: 'tool.call.toolview', key: 'render_ui' }, RenderUiRow));
```

### 2.3 三阶段契约

| 阶段 `phase` | 卡片职责 | 源码从哪来 | 交互 |
| --- | --- | --- | --- |
| `preparing` | 显示骨架 + 一行"正在生成界面…"；已解析出 `root` 就按已闭合语句先渲染 | `block.args` 惰性读取器（`args.text('ui')`）；读取器随输出增长 | 禁用。生成中的按钮**不得**可点（防半截界面误导） |
| `start` | 同上；args 完整度更高，仍可能未闭合 | 同上；读不到时回落 `block.argsRaw` | 同上 |
| `result` | 用最终源码以 `final:true` 编译；成功显示完整界面，失败进失败态 | 优先 `block.call.argsRaw`（JSON 解析后取 `args.ui`），再回落 `block.args` 读取器 | 只有 `result` 且编译成功时可交互 |

**不变量**：

1. 同一 `callId` 贯穿三阶段；`block.name` 恒为 `render_ui`。
2. 流式阶段（`phase !== 'result'`）**不报错**：括号未闭合、`root` 未到 → `pending`，只显示骨架，不显示半截错误。
3. 渐进渲染是**只增不减**的：已显示过的组件不因后续文本而消失（最终校正只允许"补全/替换同 id 节点"）。
4. 读取 `args` 的时机在渲染或构造视图时；读取器只反映已观测到的答案，禁止在 effect 里轮询缓存。
5. 兼容字段 `argsRaw` 与 result 的 `call` 必须保留读取路径（宿主旧样本仍可渲染）。

### 2.4 组件能拿到的 props

| 来源 | 字段 | 用途 | 限制 |
| --- | --- | --- | --- |
| owner payload（宿主传入注册视图） | `callId`、`toolName`、`phase`、`block`、`cwd?`、`home?`、`loadImage?`、`openFile?`、`inspect?`；PTC 子调用带 `parentCallId` | 阶段判断、读源码、可选的图片加载与"打开文件/查看轨迹" | 插件不调用 `openFile`/`inspect`（v1 不产生文件与轨迹入口）；`cwd`/`home` 只用于展示相对路径（v1 不用） |
| 会话共享标准 props（`ctx.uiSession`） | `inputActions`：`setDraft(text)`、`submit()`、`persistDraft()` 等；`sessionId` | `send` 只经 `setDraft` + `submit`；日志前缀用 `sessionId` | 只读宿主输入面；不改草稿历史、不直接调用提交以外的动作；拿不到 `inputActions` 时按 §5.4 的"正常态禁用交互"降级 |
| slot 注册期 `inject` | 按 slot 运行时共享取 `sessionId` 等 | 需要按会话缓存时的兜底 | v1 不用；用到时先登记在 28 号改动面 |

**硬约束**：组件不读写宿主 store、不订阅 Session 事件、不 require `@deepseek-ai/*` 包；交互只经 `inputActions` 与 `window.open`。

### 2.5 注入与构建

| 项 | 规则 |
| --- | --- |
| 包声明 | `package.json` 的 `dsh.client`：`platform: "web"`、`immediately: true`、`inject: ["@deepseek-ai/dsh-client-ui-conversation"]`；`dsh.bundle.patch` 指向 `cordis.patch.yml` |
| 注入 | Client 半是**单文件** `client/client.js`，内容为 `window.__ModuleLoader__.load({ id, factory })`；只 `require('react')` / `require('styles')` |
| 源码组织 | `src/*.mjs` 纯 ESM，无宿主 API、无 Node API；`build.mjs` 去掉 import/export 后同作用域拼接，并检查**顶层标识符重名**（重名直接构建失败，不静默覆盖） |
| 生成物 | `client/client.js` 是生成物，**不手改**；构建确定性（同源码 → 同字节）；每次构建记录字节数与 sha256 |
| 语言解析器复用 | `src/kit.mjs` 同时被 Host（校验）与 Client（渲染）使用；构建时内联，所以它不能 import 宿主或 Node 模块 |

### 2.6 降级矩阵（每条都在 P2 验收）

| 条件 | 界面必须显示 | 禁止 |
| --- | --- | --- |
| 插件未加载 / slot 未注册 | 宿主通用工具卡片（插件零影响） | 空白占位、报错弹窗 |
| 样式表未被宿主认领（`<style>` 注入失败） | 组件树仍渲染（无样式），控制台一条错误 | 崩溃、白屏；**不要用 `require('styles')`**——宿主模块表没有这个 specifier |
| 流式未闭合（`pending`） | 骨架 + "正在生成界面…" | 半截错误、假按钮 |
| `result` 但源码为空 / 缺 `root` | 失败态：一句人话（"界面没有生成成功"）+ 原因 + 下一步（"让 Agent 重新生成一次，或要求用文字回答"） | JSON、堆栈、英文错误码直出 |
| 解析/校验错误 | 失败态 + **第一条错误的可读原因**；不列 24 条错误墙 | 无限错误列表、把错误码当正文 |
| 未知组件 / 未实现组件 | 行内一条"未渲染：未知组件 X"（不猜、不替换成别的组件） | 静默丢弃、渲染成空白 |
| 超规模（§3.4） | 失败态说明超了哪项；组件数组超限按目录上限截断并记错误 | 静默截断关键数字 |
| 无 `inputActions` | 正常态内控件禁用，并说明"当前会话不能发送" | 假按钮、假成功 toast |
| `open` 非 http(s) | 动作清空，不打开；失败态不弹窗 | `javascript:` / `data:` / `file:` / 相对路径 |
| 工具 `execute` 校验失败 | 宿主 result 文本说明原因；卡片进失败态 | 用旧界面冒充成功 |

### 2.7 呈现位置（待拍板 V3，2026-10-18 实机发现）

**事实**：`tool.call.toolview` 能渲染，但工具调用在 Chat 里被折进"过程组"（"执行了命令，已调用工具，已读取文件等"），**默认不可见**，用户必须点开过程组才看到界面。截图与流式证据都证明了这一点（36 个组件的卡在 DOM 里、`innerText` 为空）。

**三个候选**：

| 方案 | 机制 | 可见性 | 成本 | 状态 |
| --- | --- | --- | --- | --- |
| A 工具卡（当前） | `tool.call.toolview` | 点开过程组可见 | 已完成 | 降级/兜底 |
| B 回合末尾 | `conversation.chat.turnTail`（列表 slot，owner props：turn/seq/openFile） | 回合完成即见 | 中：需把 `render_ui` 参数接进 turn 数据 | **推荐 v1** |
| C 自定义会话行 | `uiConversation.events.register` + `conversation.chat.node` 自定义 kind | 边生成边见（最接近 ChatGPT） | 高：snapshot/Location 契约耦合，版本风险 | v1.1 评估 |

**规范约束（无论选哪个）**：呈现位置改变不能改变界面内容与安全边界；B/C 落地时必须同时验证 ①重放可重建 ②禁用插件后旧卡片退化为通用工具卡 ③流式阶段有骨架且不闪错误。

## 3 · 界面语言 v1（行式语言）

### 3.1 语法

```
# 注释（整行）
root = Stack([标题, 内容, 选择])
标题 = Heading({text: '旧金山一日游', level: 1})
内容 = Timeline({title: '行程', items: [{time: '09:00', title: '渔人码头'}]})
选择 = Chips({title: '要不要调整？', items: [{label: '更轻松'}]})
```

| 规则 | 内容 |
| --- | --- |
| 语句 | `标识符 = 表达式`，一行一条；括号未闭合时换行不断句；字符串内的换行不算断句 |
| 入口 | 必须定义 `root`；没有 `root` → `no-root`，不渲染 |
| 前向引用 | 引用可以先用后写（`root` 先出现、子节点后到）；流式阶段允许暂时 `unresolved`，`final:true` 时才记错 |
| 标识符 | `[A-Za-z_$][A-Za-z0-9_$]*`；重复定义只保留第一条并报 `duplicate` |
| 字面量 | 单/双引号字符串（支持 `\n` `\t` `\r` 转义）、数字、`true` / `false` / `null`、数组 `[…]`、对象 `{key: value}` |
| 参数 | 每个组件**只接受一个位置参数**，四种形态：子组件数组 / 属性对象 / 字符串 / 无参数 |
| 组件调用 | `名字(参数)`；未知名字 → `unknown-component`，不渲染、不猜 |
| 引用 | 标识符引用解析成组件节点；循环引用 → `cycle`；超过 24 层 → `too-deep` |
| 注释 | `#` 到行尾（仅在括号外生效） |
| **不支持** | 变量、表达式求值、函数、条件、循环、模板字符串、Markdown、JSON 语法、代码围栏、注释掉的代码 |

**语言不是 JavaScript**：解析结果只是纯数据（`{__node, id, type, arg}`）；没有求值器、没有作用域、没有副作用。模型写错语法时走失败态，不"尽力猜"。

### 3.2 白名单组件（21 个，`src/catalog.mjs` 实测 `COMPONENT_NAMES.length = 21`）

| 组 | 组件（签名） | 参数与上限 |
| --- | --- | --- |
| 布局 | `Stack([子组件…])` | 子组件数组 |
| 布局 | `Row([子组件…])` | 子组件数组；横向 2–4 个，窄屏自动换行 |
| 布局 | `Card({title?, children:[…], tone?})` | `children` 必填 |
| 布局 | `Divider()` | 无参数 |
| 文本 | `Heading({text, level?})` | `level` 1–3，默认 2 |
| 文本 | `Text({text, tone?})` | `tone`：默认 / `muted` / `strong` |
| 文本 | `Callout({text, title?, tone?})` | `tone`：`info` / `success` / `warning` / `danger` |
| 文本 | `Badge({text, tone?})` | 小标签 |
| 文本 | `Code({text, lang?})` | 等宽；不做语法高亮 |
| 数据 | `Stat({label, value, hint?})` | `value` 与 `label` 都是字符串 |
| 数据 | `Table({columns:[…], rows:[[…]], caption?})` | `columns` ≤ 8；`rows` ≤ 60；单元格只放文本 |
| 数据 | `Chart({kind, data:[{label, value}], title?, unit?})` | `kind`：`bar` / `line` / `area` / `pie`；`data` 1–60 条 |
| 数据 | `Timeline({items:[{time?, title, detail?, tone?}], title?})` | `items` 1–40 |
| 数据 | `List({items:[文本…], ordered?, title?})` | `items` 1–40 |
| 媒体 | `Image({src, alt?, caption?})` | `src` 只允许 http(s)；替代文本按 §5.6 兜底 |
| 媒体 | `Gallery({images:[{src, alt?, caption?}], columns?, title?})` | `images` 1–12；每张替代文本按 §5.6 兜底 |
| 媒体 | `Map({center:[lat,lng], zoom?, markers?, route?, title?, height?})` | `markers` ≤ 30；`route` ≤ 200 点；**v1 只画本地几何，不请求瓦片**（D14） |
| 交互 | `Tabs({tabs:[{label, children:[…]}], title?})` | `tabs` ≤ 6 |
| 交互 | `Form({fields:[{name,label,type,placeholder?,options?,min?,max?,value?}], submit:{label,message?,prompt?}, title?})` | `fields` ≤ 12；`type`：`text` / `select` / `checkbox` / `slider` |
| 交互 | `Buttons({items:[{label, action, tone?}], title?})` | `items` ≤ 6；`action` 只能是 `send` / `open` |
| 交互 | `Chips({items:[{label, prompt?}], title?})` | `items` ≤ 8；点击发送 `prompt`（默认 `label`） |

- **白名单是唯一组件来源**：Host 校验与 Client 渲染读同一份目录；越界即 `unknown-component`。
- 组件目录变更（增/删/改签名）＝界面语言版本变更，必须：先登记 → 改 `catalog.mjs` → 提示词同源测试转绿 → 记账本。**不允许只改提示词**。
- `tone` 只表达语气，**不单独承担判断**：任何 tone 都必须同时有文字（02 §2 的使用规则在宿主侧的等价条款）。

### 3.3 动作只有 `send` 与 `open`

| 动作 | 语义 | 执行路径 | 限制 |
| --- | --- | --- | --- |
| `send` | 把文本作为一条**用户消息**发送给 Agent | `inputActions.setDraft(text)` → `inputActions.submit()`（同一会话输入面；不绕过输入框） | 文本非空；不拼接隐藏前缀；不伪造"用户已同意"；一次点击只发一条 |
| `open` | 在新窗口打开链接 | `window.open(url, '_blank', 'noopener,noreferrer')` | 只允许 http(s)；`javascript:` / `data:` / `file:` / 相对路径一律清空；不做预览/抓取/代理 |

- 其他动作 key（例如 `{hack: …}`、`{do: …}`）→ `bad-action`，动作清空，界面其余部分照常渲染。
- `Form` 提交也**只走 `send`**：按 `submit.prompt` 前缀 + 每行 `字段 label：值` 拼成一条消息发送；不直接调用工具、不落库、不跳页。
- `Chips` 点击 = 发送 `prompt`（缺省 `label`）；`Buttons` 点击 = 发送 `action.send` 或打开 `action.open`。
- 任何动作都**不产生宿主状态变更**（不保存、不改对象、不改设置）——写操作只能由 Agent 在下一回合经工具完成。

### 3.4 规模上限（Host 校验与门禁共用）

| 项 | 上限 | 超限行为 |
| --- | --- | --- |
| 界面源码 | **32000 字符** | 直接拒绝（`too-large`），不渲染 |
| 组件节点 | **200 个** | 停止展开并记错误，界面进失败态 |
| 嵌套层级 | **24 层** | 超深引用缩成 `__missing` 并记 `too-deep` |
| 单个字符串 | **4000 字符** | 截断并记 `too-long`（先截断再渲染，不整卡失败） |
| 错误数 | **24 条** | 只保留前 24 条；界面只展示第一条可读原因 |
| 一次回答调用 `render_ui` | **1 次** | 提示词硬约束 + 人工检查（G7），不是机械门禁 |
| 组件数组 | §3.2 各行上限 | 截断到上限并记 `too-many` |

### 3.5 错误码与表现

| 错误码 | 触发 | 界面表现 | 是否渲染 |
| --- | --- | --- | --- |
| `no-root` / `unresolved` | 缺 `root` / 最终源码引用不存在的 id | 失败态 + 原因 | 否 |
| `unknown-component` | 组件名不在目录 | 行内"未渲染：未知组件 X" | 其余渲染 |
| `bad-args` / `bad-arg-kind` / `missing-prop` / `bad-child` / `empty-children` | 参数形态或必填缺失 | 该节点退化（空参数/空子节点）并记错 | 其余渲染 |
| `bad-url` | `src`/`href` 非 http(s) | 该值清空，不加载 | 其余渲染 |
| `bad-action` | 动作不是 send/open | 动作置空，按钮不显示 | 其余渲染 |
| `cycle` / `too-deep` | 循环 / 超 24 层 | 该引用缩成缺失，不渲染 | 其余渲染 |
| `duplicate` / `trailing` / `bad-statement` | 语法错误 | 记错；语法错误所在语句失效 | 其余渲染 |
| `too-large` | 源码 > 32000 字符 | 整卡失败态 | 否 |

> 错误码是**内部契约**，不直接展示给用户；界面只展示"一句人话 + 下一步"。

## 4 · 安全与数据诚实

### 4.1 不执行代码

| 规则 | 做法 | 判据（G5） |
| --- | --- | --- |
| 只解析，不求值 | 解析器只产出纯数据节点；没有求值器、没有作用域 | `kit.mjs` 里无 `eval` / `new Function` / `setTimeout(string)` |
| 只白名单渲染 | 渲染器按 `COMPONENTS` 分发；未知组件显示"未渲染" | 白名单外组件不产生可执行分支 |
| 不用 HTML 注入 | 一律 `React.createElement`；**`dangerouslySetInnerHTML` 零使用**；不创建 `iframe` / `object` / `embed` / `srcdoc` | 静态扫描 + 单测 |
| 不加载远程代码/样式/字体 | 不插 `<script>`、`<link rel=stylesheet>`、`@import`、外部字体 | 构建产物扫描 |
| 不读本机 | 无 `file:` / 本地路径加载；不用 `fetch` / `XMLHttpRequest`（`open` 之外无网络） | 静态扫描 `fetch` / `XMLHttpRequest` / `file:` |

### 4.2 URL 只允许 http(s)

- 适用位置：`Image.src`、`Gallery.images[].src`、`Buttons.items[].action.open`、以及任何未来登记的 `src` / `href` 字段。
- 判定：`^https?://[^\s]+$`（大小写不敏感），且必须非空；空串视为"没有链接"，不报错。
- 拒绝清单：`javascript:`、`data:`、`blob:`、`file:`、`ftp:`、协议相对 `//host/…`、相对路径、含空白的 URL。拒绝后**清空该值**并记 `bad-url`，界面其余部分照常渲染。
- `open` 一律 `noopener,noreferrer`；不做后台预取、不代抓页面、不显示第三方内容预览。
- 外链是否"真实、有来源"由模型负责（提示词：没有可靠链接就不放链接）；门禁只保证**scheme 安全**，不能证明链接内容真实——这一条写进 G7 人工检查。

### 4.3 数据诚实（不编数）

| 规则 | 内容 |
| --- | --- |
| 事实来源 | 界面里的每个数字、价格、评分、地点、图片、链接都必须来自**工具结果或当前对话上下文**；提示词明文要求 |
| 无来源 | 写"未知 / 待确认"，不用估算值凑数；不把推断写成事实 |
| 不装饰数据 | 不用假趋势线、假进度、假评分补空；没有数据就不放该组件 |
| 图片/地图/链接 | 只用真实的 http(s) 地址；没有可靠图片就不用 `Image`/`Gallery`；地图不编经纬度 |
| 界面≠证据 | 界面是阅读面；"存下来当证据"属于 18 号的对象路径，不属本插件 |
| 失败即明说 | 生成/校验失败走失败态，不用"看起来完成了"的界面掩盖 |

> 与 18 号的区别：18 号用 `dataRefs: id@revision` + `basis` 做**字段级**映射校验；对话内界面没有工作台对象引用，靠**提示词 + 人工检查（G7）+ 失败态**保证诚实。**不要把 18 号的 dataRefs 硬塞进对话界面**（D15 推荐不写 view 对象）。

### 4.4 不存数据、不调模型、不新增入口

| 项 | 现状/要求 | 判据 |
| --- | --- | --- |
| 业务数据 | 插件不建表、不写文件、不缓存界面内容；唯一持久化是 Session 日志里的工具参数 | 仓库与安装目录无数据文件；无 `writeFile` |
| 模型调用 | Host 半不注册 provider、不发 LLM 请求；Client 半不持凭据 | 静态扫描；`package.json` 无模型依赖 |
| 入口 | 不新增一级入口、页面、导航、会话节点类型；Slot 只替换工具卡片内部 | 与加载前对比宿主信息架构不变 |
| 遥测 | 不上报界面源码、点击、曝光；日志只打统计（节点数/错误数/耗时） | 代码扫描 + 人工检查 |

### 4.5 审计与隐私

- 界面源码进入 Session 日志，属于**用户可见内容**，按会话数据管理（宪章 v1.3 补：数据不出本机；不随包发布，不写进仓库）。
- 日志与截图证据一律脱敏：不含 token、本机绝对路径、第三方凭据；需要引用真实对话时先脱敏再进账本。
- 用户点 `open` 的链接是可观察的对外动作：只在用户点击时打开，不做批量打开、不做自动跳转。

## 5 · 渲染规则（宿主主题）

> **视觉权威说明**：本插件渲染在**宿主对话卡片**里，用的是宿主主题；[02-VI 规范](02-VI规范-v1.0.md) 的 `--ws-*` 色板与工作台组件是**工作台页面**的视觉基线，不适用于这里。本插件只借 02 的四项原则：字阶唯一、克制（不新增颜色/字号/图标）、四态齐全、无装饰动效。

### 5.1 容器与布局

| 项 | 规则 |
| --- | --- |
| 宽度 | 占满工具卡片内容宽；`min-width: 0`；任何层级不撑破卡片 |
| 纵向节奏 | 块间距 12px；卡片内边距 14/16；`Stack` 纵向、`Row` 横向且允许换行 |
| 嵌套 | 一块内容最多两层容器嵌套（Card 内不再套 Card） |
| 图表/地图/表格 | 各自有最大高度与内部滚动；页面不因界面变长而失去输入框 |
| 空容器 | 空数组不渲染空壳（`empty-children` 记错并不渲染空 Card） |

### 5.2 颜色：只用宿主 token

**允许的 token**（2026-10-18 现行渲染器实际使用；新增前必须从宿主 Theme token 表取实际名称并登记）：

| token | 用途 |
| --- | --- |
| `--dsw-alias-label-primary` | 正文 |
| `--dsw-alias-label-secondary` | 次要文字 / 辅助 |
| `--dsw-alias-bg-layer-1` | 卡片底 |
| `--dsw-alias-bg-layer-2` | 骨架/次级底 |
| `--dsw-alias-border-l1` / `--dsw-alias-border-l2` | 分隔线 / 虚线边界 |
| `--dsw-alias-brand-primary` | 进度指示点、必要的强调 |
| `--dsw-alias-state-warn-primary` | "未渲染/未知组件"提示 |

规则：

- **不写字面色值**（`#fff`、`rgb()`、`hsl()` 一律禁止）；不新增 token；不覆盖宿主 token。
- `tone`（info/success/warning/danger）只能在**已有状态语义**下使用，且必须同时有文字；颜色不单独承担判断（02 §2 的等价条款）。
- 深浅色两套由宿主 token 决定，插件不写 `prefers-color-scheme` 分支、不硬编码深浅。

### 5.3 字阶与字重（唯一 5 档）

| 层级 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| H1（`Heading level=1`） | 20 / 28 | 600 |
| H2（`Heading level=2`） | 17 / 26 | 600 |
| H3（`Heading level=3`、`Card` 标题） | 15 / 22 | 600 |
| 正文（`Text`、表格、表单、按钮） | **14 / 22** | 400 |
| 辅助（`Badge`、caption、骨架状态文字） | 12 / 18 | 400 |

- 字号集合固定为 `{20, 17, 15, 14, 12}`；**新增字号 = 规范变更**，走第九条流程。
- 字重只用 400 / 550 / 600；**禁止 700**；550 只用于数字或强调。
- 数字一律 `font-variant-numeric: tabular-nums`。
- 行高随字号成对登记；不允许 14/24、15/24 这类半档（落地差异见 28 §3，P2 收口）。

### 5.4 四态（缺一不算完成）

| 状态 | 触发 | 必须显示 | 下一步 |
| --- | --- | --- | --- |
| 加载中 | `preparing` / `start`；或 `result` 尚未完成首次渲染 | 骨架 + 一行"正在生成界面…"；`aria-busy="true"` | 无（自动推进）；超时后给"重新生成/用文字回答" |
| 空 | `result` 且源码为空 / 未定义 `root` | 一句人话（"界面没有生成成功"）+ 具体原因 | "让 Agent 重新生成一次"或"要求用文字回答" |
| 失败 | 解析/校验/渲染/工具执行失败 | 一句人话 + 第一条可读原因 | 重试（下一次调用）或改用文字 |
| 正常 | `result` 且编译成功 | 组件树；交互可用（无 `inputActions` 时控件禁用，并在旁边说明"当前会话不能发送"） | — |

**正常态的"不可交互"约束**：没有 `inputActions` 时不能把控件做成"看起来能点"——按钮/表单/建议用禁用样式，旁边一句说明；不得伪造发送成功，也不得隐藏整个界面。生成中同理（§2.3）。

**文案要求**：不出现技术术语/错误码/JSON/堆栈；失败态必须有下一步；不写"我为你生成了界面"这类实现性文案（17 C5）。

### 5.5 动效

- 允许的只有**生成中的进度指示**：骨架微光或状态点**二选一**，周期 ≤1.4s；`prefers-reduced-motion: reduce` 时必须静止。
- 禁止：打字机、逐项渐入、弹跳、闪烁、旋转加载器、滚动动画、hover 位移、装饰性渐变。
- 其他状态（空/失败/正常）**零动画**。
- 引用 02 VI「安静」与宪章八「装饰性动效不做」：动效只用于表达"还在进行"，不用于吸引注意。

### 5.6 无障碍

- 语义：标题用 `Heading` 映射标题标签；按钮是真 `<button>`（可用键盘 Enter/Space）；表单控件都有 `<label>`；状态文字 `role="status"`；图片替代文本不得为空——`alt` 缺失时用 `caption`，仍缺则用「图片」兜底，并记 `missing-prop`。
- 键盘：所有交互可 Tab 到达；焦点环用宿主 token 的焦点样式（不自定义颜色）；生成完成的界面不抢焦点。
- 对比度：正文 ≥4.5:1、关键边界 ≥3:1（由宿主 token 保证，插件不自造颜色）。
- 触摸目标 ≥44×44（390 宽度下按钮/页签/建议 chip）。

### 5.7 移动端 390

| 项 | 规则 |
| --- | --- |
| 栅格 | 单列；`Row` 自动换行，不横向滚动 |
| 表格 | 外层横滚容器（可聚焦、有可见滚动提示）或折叠成卡；单元格不换行到不可读 |
| 图表 | 宽度 100%，高度 ≤240；标签最多 6 个，过多时模型侧收（提示词） |
| 地图 | 高度 ≤240，只画本地几何（D14） |
| 弹层 | 本插件不弹窗；`Tabs` 内容在窄屏保持单列 |
| 遮挡 | 界面底部不与输入区/粘性栏重叠；不出现横向溢出 |

## 6 · 可复现与重放

1. **唯一事实源**：一次界面生成的完整定义 = `render_ui` 的工具参数 `ui` + 工具返回值 `{ok, nodes, errors}`，两者都在 Session 日志里。插件不另存快照、不缓存渲染结果。
2. **重放**：同一 Session 日志重放 / fork 时，卡片用同一 `ui` 源码重新编译渲染；不调用模型、不重新生成、不依赖生成时的内存状态。
3. **确定性**：同源码 + 同插件版本 → 同组件树、同节点数、同错误码；门禁在 G8 校验 `data-oui-nodes` / 根类型 / 错误数一致。
4. **语法版本**：界面语言 v1 冻结。插件升级时：
   - 新增组件 → 旧源码不受影响；
   - 删除/改签名组件 → 旧源码在 `result` 时显示"未渲染：未知组件 X"，**不崩溃、不静默改写**；
   - 语法本身变更 = 新语言版本，必须登记并保留 v1 解析器。
5. **不伪装重放**：重放失败就显示失败态；禁止"重放时偷偷让模型重写一遍"（宪章七：不锁模型、不用当前版本才懂的东西）。
6. **可核对**：账本记录插件版本、构建 sha256、宿主版本；同类界面的节点数与耗时作为回归指标。
7. **v1 不做**：导出、跨会话迁移、把界面转成工作台对象（D15）。

### 7.2 与 18 号「生成视图」的分工（两条渲染面，互不代替）

| 维度 | 18 号 · 页面内生成视图 | 19 号 · 对话内智能界面 |
| --- | --- | --- |
| 渲染位置 | 工作台页面（项目/任务/知识详情区块） | 宿主对话的工具卡片 |
| 持久化 | `view` 对象落库（模板 + 参数 + `dataRefs`） | Session 日志里的工具参数；**不落库** |
| 数据契约 | `view` 对象 + `dataRefs: id@revision` + `basis` | 模型按上下文生成；无对象引用；靠提示词与人工检查 |
| 视觉 token | `--ws-*`（02 VI） | `--dsw-alias-*`（宿主主题） |
| 基础结构 | 4 类模板（risk-matrix / timeline / compare-table / blocker） | 21 个白名单组件 + 行式语言 |
| 交互 | `open-subject` / `save-as-judgment` / `save-as-brief` | 只有 `send` / `open` |
| 失败/失效 | `stale`（引用 revision 变化） | 失败态 + 重放一致性；无 stale 概念 |
| 保存/导出 | 可存观点、可导出文档 | v1 不保存、不导出 |
| **共用原则** | **有依据、可复现、不编数、不新增入口、用户动作触发** | 同左 |

**互不代替**：对话里生成的界面**不写工作台 view 对象**（D15）；工作台页面**不渲染对话界面的源码**；同一问题可能"对话里有界面、工作台里没有产品视图"，这个边界在文案与文档里说清，不假装两边是同一功能。

### 7.3 与 27 号的关系

- 27 §2 D11 的 B 线（宿主插件）在本规范落地；27 的 G0–G4（工作台页面内生成视图）**不受阻**，两条线并行、各自验收。
- 27 附录 A 要求"生成内容的视觉规范另写一份（宿主主题 ≠ 工作台 VI）"——就是本规范 §5。
- 数据来源原则共用 18 号的"数据有引用 / 生成有依据"；但本插件**没有** `dataRefs` 结构，不引用工作台对象，不跨插件取数（13 §4：只通过已核验的受控接口；v1 连取数都不需要）。
